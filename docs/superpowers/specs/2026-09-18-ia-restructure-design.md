## 0. 한 줄

> 문제는 **정보량이 아니라 주소 체계**다. 지표 144개가 "어느 페이지에 있는가"로만 배치돼 있고, "무엇을 묻고 싶은가"로는 묶여 있지 않다.
> 개편의 뼈대 4가지 — ① **지표 레지스트리 하나로 분류 체계 7개를 합치고 중요도(tier)를 부여**, ② **1차 네비 13 → 6 + 레일**, ③ **한 섹션 = 한 질문 + 탈출구 하나**, ④ **지표마다 원본 화면 1곳(canonical)을 정하고 나머지는 요약 + 링크**.
>
> 가장 큰 발견: KOSPI가 **14곳**, USD/KRW가 **12곳**에 각각 원본처럼 떠 있고, 분류 체계가 코드 안에 **7개** 따로 돌아간다. 반대로 매일 수집만 하고 아무 화면에도 없는 데이터가 **22건**(미노출 지표 21 + BTC 1,826포인트)이다.

### 2.3 우리가 가져올 원칙 8가지

1. **자산군으로 묶는다** — 출처(ECOS/FRED/pykrx)나 수집 방식이 아니라, 사용자가 부르는 이름으로.
2. **한 섹션 = 한 질문 + 탈출구 하나** — 섹션 제목은 질문의 답이고, 심화 경로는 「전체 보기」 한 개만.
3. **10 / 100 규칙** — 홈·요약 섹션은 10건, 전용 화면은 100건, 더보기는 1회 +100.
4. **첫 화면은 답, 아래는 탐색** — 홈 첫 화면 ≤1,583px 유지(SEED P5 성과), 나머지는 기본 접힘.
5. **개인 영역은 페이지가 아니라 패널** — 관심·최근 본·투자현황·캘린더는 우측 레일로.
6. **숫자 옆에 시각과 이유** — as-of 배지 4종 + `news` 16주제 매칭 한 줄.
7. **질문을 UI로 만든다** — 목적 프리셋(토스 스크리너 방식)을 경제 지표에 적용.
8. **원본은 한 곳** — 지표마다 canonical 화면 1개, 다른 화면의 동일 지표는 **요약 + 원본 링크**로 표시.

### C4. 섹션 규격 — "한 섹션 = 한 질문"

- 섹션 제목은 **명사구가 아니라 답**: 「거래대금 Top20」 → 「오늘 돈이 몰린 종목」(부제 = 거래대금 상위 20).
- 이모지 접두 **전면 폐지**(D5). 제목은 평문 + 필요 시 상태 배지.
- 모든 섹션 제목은 `<h2>`/`<h3>`로 승격(D3). `div.widget-title` 146개 → 시맨틱 헤딩 + 페이지 목차 자동 생성.
- 섹션 우상단 고정 3요소: **기간 세그먼트 · as-of 배지 · 「전체 보기 ›」 하나**.
- 명명 사전을 한 곳에 둔다(`js/terms.js`): `WTI 유가`/`WTI 원유` → **「WTI 원유」**, `글로벌 주요 지수 현황` → **「글로벌 지수」**, `KOSPI 지수` → **「KOSPI」**.

### C5. 거시 50지표 — 주제 탭 + 우선순위 (D2 해소)

- `cat` 10종을 **6개 주제 탭**으로 승격: 경기(18) · 물가(9) · 고용(6) · 통화·금리(8) · 무역·외환(3) · 소비·부동산(4). 탭은 URL에 싣는다(`?p=macro&t=price`).
- 각 탭 기본 노출 = **대표 지표 4개 카드 + 나머지 표 1개**(접힘). 현재의 55카드 동시 노출을 끝낸다.
- 국가 필터는 유지하되 **탭 안의 칩**으로 내린다(현재는 페이지 최상단 필터).
- 지표 카드에 **밴드 내 위치**를 넣는다(토스의 52주 범위 바) — 값만으로 판단 못 하는 문제.

### C6. 목적 프리셋 — 질문을 UI로 (토스 스크리너 이식)

지표를 찾아다니지 않고 **질문을 고른다**. 좌측 또는 홈 하단에 프리셋 8종, 조건은 사람 말 칩으로 노출:

| 프리셋 | 조건(칩 표기) | 재료 |
|---|---|---|
| 오늘 뭐가 움직였나 | 「등락률 · 오늘 · ±2% 이상」 | `stockMovers`,`indices` |
| 금리는 어디로 | 「기준금리 · 최근 12개월」 + 「국고10년 vs 미10년」 | `yieldCurve`,`economicIndicators` |
| 환율 부담 | 「USD/KRW · 60일 · +3% 이상」 | `fx` |
| 물가 온도 | 「CPI·PPI · 전년비」 | `economicIndicators` |
| 외국인은 사는가 | 「투자자별 · 5일 누적」 | `investorTrading` |
| 부동산 온도 | 「가격지수 · 거래량 · 주담대」 | `realestate` |
| 원자재 충격 | 「에너지·금속 · 20일 변동」 | `commodities`,`lmeInventory` |
| 이번 주 일정 | 「영향력 높음 · 7일」 | `economicCalendar` |

결과 화면에는 토스처럼 **「조건에 맞는 지표 · N건」**과 기준 시각을 적는다.

### C6-B. 지표 레지스트리 — 7개 분류를 1축으로 (D11·D13 해소)

개편의 **기반 작업**. 지금은 사이드바 그룹·비교차트 85·거시 50·메르 48·뉴스 16·노트 4·`sources` 33이 각자 따로 논다. 이것들을 **지표 하나당 한 행**인 레지스트리 파일(`js/indicators.js`)로 합친다.

```js
// 지표 1건 = 1행. 화면·분류·중요도가 전부 여기서만 정의된다.
{ id:'usdkrw', label:'USD/KRW', unit:'원',
  asset:'fx',            // 자산군 = 1차 네비 축 (index|equity|fx|rate|commodity|realestate|flow|macro)
  topic:'외환',           // 거시 주제 (경기·물가·고용·통화·무역·소비)
  tier:1,                // 1=대표(홈 노출) 2=주요 3=상세표 전용
  canonical:'market#fx', // 원본 화면 — 다른 화면은 요약 + 링크
  news:'외환',            // news 16주제 매칭 키 (한 줄 이유 생성용)
  data:'fx.USDKRW', series:'history.fx.USDKRW',
  merLens:'usdkrw' }     // 메르 렌즈 레이어와의 매핑
```

효과: ① `tier`가 생기면 "무엇을 크게 보여줄지"를 화면이 아니라 데이터가 정한다(D13) ② `canonical` 한 칸으로 중복 14곳이 원본 1 + 요약 13이 된다(D6) ③ 비교차트 카탈로그·거시 카드·메르 렌즈가 같은 `id`를 쓰면 매핑 테이블이 필요 없어진다(D11) ④ 레지스트리에 없는 데이터가 남으면 그게 곧 **미노출 21건·BTC**의 처리 결정 목록이 된다(D10) ⑤ `dataPath`가 죽은 3건은 빌드 때 검출된다.

전역 검색·지표 즐겨찾기·정렬(D12)도 이 레지스트리 위에서만 한 번에 구현된다 — 검색 대상은 레지스트리 행, 즐겨찾기는 `id` 배열.

### C7. MY 레일 (D8 해소)

- 우측 **56px 아이콘 레일** + 펼침 **312px 오버레이**(본문 폭 불변). 항목 4 = 관심 · 최근 본 · 투자 현황 · 오늘 일정, 하단에 테마 토글.
- 저장은 `localStorage`, **PIN은 「투자 현황」 패널 안에서만** 요구(현행은 페이지 자체가 잠김).
- 빈 상태는 빈 화면이 아니라 가치 제안 한 줄 + CTA(네이버 패턴: 16px/600 + 14px/400 회색 + 버튼).
- `?p=portfolio` 등 기존 링크는 레일을 연 상태로 해석.

### C8. 맥락 한 줄과 as-of (D9)

- **as-of 배지 4종**: 실시간 / N분 지연 / 장마감 + 시각 / N시간 전. 「LIVE에서는 침묵」을 기본값으로.
- **한 줄 이유**: 지표 ↔ `news` 16주제 매핑 테이블 하나로 생성(예: `fx.USDKRW` → `news.외환` 최신 1건 제목 12자 요약). AI 호출 없이 **규칙 기반 우선**, 실패 시 줄을 비운다(날조 금지).
- 좌측 사이드바의 **데이터 소스 표시등 8개와 「⚠ 지연 6 · 누락 1」은 설정 > 시스템 진단으로 이동**. 사용자 화면에는 배지만 남는다.

## 7. 선행 기획 v2와의 관계

v2(`2026-09-09-naver-benchmark-ux-design.md`, 구현 미착수)를 **폐기하지 않고 흡수**한다.

- **승계**: 자산군 축 재편(K3) · 홈 하이브리드(K2·C2) · as-of 배지(C5) · 우측 MY 레일(C4) · 토큰 정합(C6) · 증권 캘린더(C7) · 「10/100」·「한 섹션 한 질문」 원칙.
- **수정 3건**:
  1. **1차 7항목 → 6항목.** 「해외·글로벌」을 1차에서 내린다 — 개별 종목 데이터가 전부 국내이기 때문(§C1).
  2. **「수급」을 1차로 올린다.** v2는 `investor`를 거시>통화 앵커로 흡수했으나, `investorTrading`(400일)·`stockFlows`·`nps` 세 도메인이 한 질문("누가 사고 파는가")을 이루므로 독립 축이 맞다.
  3. **D2 진단 정정.** v2는 거시를 "평면 나열, 주제 축 없음"으로 적었으나 실제로는 `cat` 그룹핑이 **이미 구현돼 있다**(`buildMacroIndicatorTable`). 문제는 분류 부재가 아니라 **접힘·우선순위 부재**다.
- **v2의 판정 수치는 인용하지 않는다** — 헤더 배지(28건)와 실제 판정표(30행)가 불일치하고 「표 설정」 항목이 중복돼 있다(사료 검증 결과).
- **새로 추가**: **지표 레지스트리(C6-B)** — v2에 없던 축이자 본 기획의 기반. 7개 분류 공존·중복 14곳·중요도 필드 부재는 화면을 옮겨서는 안 풀리고, 데이터 한 층을 세워야 풀린다. 그 외 토스 축(목적 프리셋 C6 · 한 줄 이유 C8 · 요약 문장형 일정 C3) · 단일 원천 지도(C2) · 섹션 규격/명명 사전(C4).
