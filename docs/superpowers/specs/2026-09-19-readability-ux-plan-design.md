## 0. 한 장 요약

**문제는 모바일이 아니라 데스크톱이다.** 9월 18일 모바일 개편으로 390px 본문은 14px가 되었는데,
1440px 본문은 여전히 **12px/19 w400이 731곳**으로 지배적이다. 큰 화면이 작은 화면보다 읽기 어렵다.
벤치마크는 반대다 — 네이버 PC 14px w500, 토스 13px w600.

그 외 네 가지가 같은 뿌리에서 나온다: 텍스트 위계가 2단뿐(벤치 3~4단), 같은 지표가 화면마다
다른 자릿수로 나오고(G6 실패), 데이터 블록에 **기준 시점 표기가 사실상 없으며**(10페이지에서
신선도 요소 3개), 모바일 첫 화면에서 **첫 숫자가 930~975px 아래**에 있다(네이버 142px·토스 157px).

개편은 8개 항목(C1~C8), 4단계(P0~P3)다. 전부 기존 단일 원천(SEED 브리지 · `ECON_IND` ·
`INDICATOR_DECIMALS`)을 건드려 한 곳에서 끝내고, 게이트 4개(G7~G9·M8)를 추가해 되돌아가지 못하게 한다.

## 2. 현행 진단

### D1 — 데스크톱 본문이 한 단계 작고 한 단계 얇다 (최우선)

| | 본문 지배값 | 보조 | 비고 |
|---|---|---|---|
| economic-site 1440 | **12px / 19 w400 ×731** | 12px w500 ×398, 13px w400 ×100 | 14px는 84곳뿐 |
| economic-site 390 | 14px / 19 w400 ×220 | 14px w500 ×90 | 9/18 개편 결과 |
| Npay증권 PC | 14px / 19 **w500** | 12~13px | 행간 1.33 |
| Npay증권 반응형 | 13px / 19 w500, 14px / 20 w400 | 12px / 18 | |
| 토스증권 PC | 13px / 20 **w600** | 12px / 16 w500 | 크기 대신 굵기로 위계 |

원인은 별칭 층이다. `index.html:1046-1051`에서 `--fs-body: var(--font-size-sm)`(13px),
`--fs-label: var(--font-size-xs)`(12px)로 묶여 있고, 실제 화면은 대부분 xs 계열을 쓴다.
`@media (max-width:480px)` 블록(`index.html:549-552`)만 xs/sm/md/base를 13/14/14/16으로
올려놨기 때문에 **모바일만 커졌다**.

### D2 — 텍스트 위계가 2단

우리: `#1A1C20`(×950) · `#555D6D`(×806) 두 단계가 전부. 벤치는 3~4단이다 —
네이버 PC `#000` / `#4E5052` / `#87898E`, 토스는 알파 `.89 / .77 / .61 / .47`.
지금은 "값의 꼬리표"와 "설명 문장"이 같은 회색이라, 밀도가 높아질수록 뭘 먼저 읽을지 단서가 없다.

### D3 — 기준 시점(as-of) 표기가 없다

구조 감사에서 신선도/기준시각 요소는 **10페이지 통틀어 3개**(macro·realestate·merlens 각 1).
벤치는 화면 좌상단에 장 상태를 상시로 두고(네이버 「KRX 정규장 09:00~15:30」·「장마감」,
토스 「국내 장 닫힘」), 랭킹 표에는 「오늘 14:35 기준」을 붙인다.
우리 데이터는 소스마다 갱신 주기가 다르다(10분·1시간·일 1회·토스 스냅샷 PC 의존) — **여기서
기준 시점 부재는 벤치보다 더 위험하다**.

### D4 — 같은 지표, 다른 자릿수 (G6 실패)

`USD/KRW 1380`이 한 화면에서 0자리, 다른 화면에서 2자리. `S&P 7650`이 1자리 vs 2자리.
10페이지 중 8페이지에서 재현된다.

### D5 — 산문 줄이 90자까지 간다 (G4 실패)

`realestate` 84자, `investor` 91자(기준 50자). 한글은 30~45자가 적정이다.
벤치는 산문 블록을 열 폭으로 제한한다(네이버 AI 브리핑 블록 폭 ≈ 640px).

### D6 — 차트 계열색이 글자에 쓰인다 (G1 실패)

`macro` 라이트에서 13px `#B6C4FF` on 흰 배경 = **1.7:1**(필요 4.5), `#7E8AFF` = 3.0:1.
「기준금리 · 5개국」, 「국채 수익률 · 2개국」 같은 꼬리표다. 계열색은 선·면에만 쓰고
글자는 텍스트 토큰을 쓴다는 규칙이 그 자리에서 빠졌다.

### D7 — 인라인 색이 페이지당 900~1,150곳

`G5 인라인색`: notes 913 → merlens 1,149. 더해서 merlens에는 **브라우저 기본 링크색
`rgb(0,0,238)`이 35곳**(토큰을 아예 거치지 않는 `<a>`). 테마 전환에서 빠지는 잠재 결함이다.

### D8 — 화면 간 밀도 규칙이 없다

### D9 — 모바일 첫 화면에 숫자가 없다

첫 데이터까지의 거리: `calendar` 975px · `realestate` 957px · `dashboard` 930px.

## 3. 설계 원칙

벤치 두 곳에서 공통으로 관찰된 규칙 중 **우리가 채택할 것**과 **버릴 것**을 먼저 못 박는다.

**채택**

1. **크기 5단 + 색 3단.** 폰트 크기 종류를 5개 이하로 묶고, 위계는 색으로 만든다(네이버형).
2. **색은 데이터에만.** 표면·테두리·텍스트는 무채색, 유채색은 등락·상태·계열뿐. (기존 원칙 재확인 — D6가 위반)
3. **데이터는 행이다.** 카드 중첩 금지, 표 행 32~40px(데스크톱)/44px(모바일). 현행 36/44px는 이미 맞다.
4. **숫자는 한 덩어리.** 값(굵게) 바로 아래 등락, 단위는 값 뒤 작게, tabular-nums.
5. **지금 보는 숫자가 언제 것인지 화면이 먼저 말한다.** 블록마다 as-of.
6. **이동은 라인탭, 조건은 칩.** 모양이 역할을 말한다.
7. **첫 화면은 숫자로 시작한다.** 안내·컨트롤은 그다음.

**버릴 것**

- 토스식 **본문 w600**: SEED 스케일에 600이 없다(400/500/700). 굵기 대신 크기+색으로 간다.
- 토스식 **알파 텍스트 색**: 다크 전환에서 배경과 곱해져 대비 계산이 흔들린다. 불투명 3단으로.
- 토스식 **자체 서체**: Pretendard 유지.
- **전면 3열 셸**: 단일 `index.html` 구조에서 비용 대비 효과가 낮다. 홈 한 곳만 시범(C8).

## 4. 개편안

### C1 — 데스크톱 타이포 재기준 (D1, D10)

`index.html` 브리지 옆에 **데스크톱 재매핑 블록**을 둔다. 모바일 블록(`max-width:480px`)의 대칭형이다.

```
:root { /* ≥481px */
  --font-size-xs:   t2 12px   /* 꼬리표·단위 — 유지 */
  --font-size-sm:   t3 13px   /* 표 셀·목록 보조 */
  --font-size-md:   t4 14px   /* ← 13 에서 상향: 본문 기본 */
  --font-size-base: t4 14px
  --font-size-lg:   t6 18px
}
```

- 별칭 층(`index.html:1046-1051`)의 `--fs-body`를 `sm`→`md`로 옮긴다. 사용처가 html 502 + js 378곳이라 개별 수정은 하지 않는다.
- 본문 굵기 기본을 **w500**으로(네이버 PC와 동일). SEED에 500이 있다.
- 읽는 글(설명·주석·요약)은 14px, 값·꼬리표·단위는 12~13px로 남긴다.
- 목표: 1440에서 12px 미만 비율 **10% → 5%**, 12px 지배값이 14px로 교체.

### C2 — 텍스트 색 3단 (D2)

브리지에 세 이름을 세운다(값은 현행 팔레트에서 뽑는다).

| 이름 | 라이트 | 용도 |
|---|---|---|
| `--color-fg` | `#1A1C20` | 값·제목 |
| `--color-fg-muted` | `#555D6D` | 본문·설명 |
| `--color-fg-subtle` | `#8A92A0`(신설) | 꼬리표·단위·메타 |

`.econ-meta`·`.econ-stat__unit`·표 헤더를 subtle로 내리고, 본문은 muted, 값은 fg.
대비는 subtle도 4.5:1을 넘는 값으로 고른다(다크는 대칭값).

### C3 — 숫자 블록 표준 (D4)

- 컴포넌트 `.econ-num`: `값(fg, w700, tabular-nums)` / `등락(up·down, 값 바로 아래)` / `단위(subtle, 값 뒤)`.
  현재 화면마다 값·등락 배치가 갈린다.
- 자릿수는 `INDICATOR_DECIMALS` **단일 원천만** 참조한다. 지금 G6가 실패하는 1380(USD/KRW)·7650(S&P)은
  포매터를 거치지 않는 경로가 남아 있다는 뜻 — 그 경로를 찾아 없앤다.
- 게이트: G6 실패 0.

### C4 — as-of 규격 (D3)

- **화면 머리**: 시장 상태 배지(`KRX 정규장 / 장마감 / 휴장 / 실시간`) — 네이버 패턴.
- **블록 머리**: 각 위젯 제목 줄 오른쪽에 기준 시각. 규칙은 기존 신선도 칩과 같다 — **정상이면 침묵**,
  지연·전일·집계중일 때만 표기(`LIVE 침묵` 원칙 유지).
- **값 옆**: 소스가 다른 값이 한 표에 섞일 때만 작은 점 배지.
- 데이터를 그리는 위젯의 as-of 커버리지 100%를 게이트로 잰다(G8).

### C5 — 첫 화면 규격 (D9)

- 모바일 `firstData ≤ 420px`(벤치 142~157px, 현행 930~975px). 헤더 아래 첫 블록은 **지표 스트립**.
- 안내·면책·컨트롤은 첫 데이터 아래로. `econFoldControls`를 첫 화면에 우선 적용.
- 데스크톱도 같은 규칙(첫 데이터 ≤ 320px).
- 게이트 M8로 고정.

### C6 — 밀도 규칙 (D8)

- 목표: **데스크톱 ≤ 4.0화면 · 모바일 ≤ 4.0화면**. 현재 위반은 merlens-d 7.45, macro-m 4.53, realestate-m 4.24.
- 표는 **5행 + 더보기**가 기본(벤치 공통). 긴 표는 상위 N행 + 「나머지 N개 보기」 — merlens 모바일에서 이미 검증된 패턴을 데스크톱에도 적용.
- 한 화면의 버튼 상한 120개를 경고선으로(merlens 240·macro 119).
- 화면 상단에 **요약 한 줄**(카운트 + 가장 중요한 3개)을 두고 표는 접는다.

### C7 — 발견 경험 (벤치 채택)

- **이름 붙인 질문**: 기존 목적 프리셋 8종을 토스 스크리너 어법으로 다시 쓴다
  (「연속 상승세」·「저평가 성장주」처럼 목적어가 있는 이름).
- **한 줄 이유**: 지표 KPI 아래 뉴스/메르 신호에서 뽑은 한 줄(이미 P3에서 도입 — 커버리지를 지수·환율·원자재로 확대).
- **52주 위치 바**: 최저–최고 막대 + 현재 점. 네이버·토스 공통 패턴이고, 숫자 두 개보다 빠르다.
- **스파크라인**: 목록 행에 7일 미니 차트(네이버 랭킹 행 패턴). 행 높이 36px 유지 범위에서.

### C8 — 셸 (시범)

- 홈만 **좌 목록 / 중 상세 / 우 개인화** 3열로. 좌측에서 지표를 고르면 중앙만 교체(페이지 이동 없음).
- 우측은 기존 MY 레일(56px + 312 오버레이)을 그대로 쓴다.
- 1024 이하에서는 기존 1열로 접힌다(`.g-side` 유틸 재사용).

## 9. 리스크

### 기획안에서 수정된 판단 3건

1. **G9 데스크톱 상한 4.0 → 5.5.** 벤치마크 실측이 네이버 PC 홈 5.6화면·토스 홈 5.7화면이다.
   4.0 은 모바일 기준을 데스크톱에 그대로 옮긴 잘못된 목표였다.
2. **M8 첫 데이터 상한 320/420 → 420 공통.** 벤치(142~157px)는 페이지 목차·탭 셸이 없는 구조다.
   그 층을 없애는 것은 IA 결정이라 이 게이트의 범위가 아니다 — "첫 화면 절반 안"으로 잡았다.
3. **G6 는 산문을 세지 않는다.** 뉴스 제목의 "1,380원"이 표의 1,380.16 과 충돌로 잡혔다.
   값 슬롯끼리만 비교하도록 게이트를 고쳤다(`readability.mjs`). 남아 있던 진짜 불일치
   (지수 카드, NPS 운용규모)는 포매터로 해결했다.

### C8 · G7 2차 (같은 날 후속)

**C8 홈 3열.** 「행 = 메인 차트」 모델(`selectGlobalIndex`)은 이미 있었는데 목록(`homeSecWatch`)과
차트(`homeSecMain`)가 세로로 떨어져 있어 그 관계가 화면에 보이지 않았다. 글로벌 지수 목록을
메인 섹션 안으로 옮겨 **좌 목록(3) · 중 차트(6) · 우 등락 Top10(3)** 으로 세웠다. 우측 개인화는
기존 MY 레일이 담당한다. 남은 시장 분위기 위젯은 전폭(12)이다. ≤1024 에서는 기존처럼 1열로 접힌다.

좁은 칼럼에서 등락률이 두 줄로 깨져, 목록의 현재가·등락률을 **한 칸에 값 위·등락 아래**로 합쳤다
(`.econ-numcell`, §C3 숫자 블록 규칙). 표 머리도 「현재가 · 등락률」 3열로 줄었다.

**G7 2차.** 화면에서 실제로 위험한 것은 인라인 `color` 전체가 아니라 **토큰을 거치지 않은 하드코딩
색**이다(다크에서 대비가 무너진다). 36곳을 토큰으로 바꿨다 — 설명 모달의 위험/탐욕 색
`#b91c1c`·`#0f6e56` 32곳 → `--ind-neg`/`--ind-pos`, PCR 보라 `#9b59b6` 3곳 → `--c-txt`,
카테고리 갈색 `#854f0b` → `--c-txt-dim`, 캡션 `#6b7280`·오류 `#ef5350` 3곳 → 토큰.
게이트의 감시 목록(`RAW`)에 그 색들을 넣어 재발을 막는다. 색 있는 배경 위의 `color:#fff` 는 남겼다.
