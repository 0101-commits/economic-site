## 1. 진단

### U1 — 숫자 표기를 정하는 메커니즘이 8가지다 (P0)

`raw/FORMAT-AUDIT.md`. 자릿수를 정하는 독립 경로가 여덟이고, 가장 넓은 것이 **하드코딩 `toFixed(n)` 285곳**이다.

| 목적 | 독립 구현 수 | 증상 |
|---|---:|---|
| 지표값 자릿수 고정 | **9** | 로케일·기본자릿수·null 표기가 제각각 |
| 등락률 표기 | **5** | `▲ 1.65%` / `+1.65%` / `(+1.65%)` 세 모양이 공존 |
| 원화 금액 | **3** | `₩1,234,567`(접두) vs `1,234원`(접미) |
| 큰 수 축약 | **4** | 억·조 임계값이 서로 다름 |
| 결측 표기 | **3** | `—` / `-` / 빈 문자열 |

**지표 레지스트리(`window.ECON_IND`, 141행)는 이 목록에 없다.** 호출부 11곳은 전부 내비게이션·라벨·검색용이고
표기에는 한 번도 쓰이지 않는다. 레지스트리에 `unit`은 50%만 있고 `decimals`/`scale`/`sign` 필드는 아예 없다.

실제로 어긋나는 자리(전부 파일:줄 확인):

- **C1 USD/KRW 네 가지 표기** — `1,372.58`(`app1:12638`) · `1,372.6`(`app1:9250`) · `1372.6`(천단위 없음, `app6:294,521`) · `1,372.58원`(`app3:68`)
- **C3 실동작 오류** — `app1:12624`의 지역 `fmt(v, kind)`에 **숫자를 넘기는 호출이 11곳**이다. `INDICATOR_DECIMALS[4]`가 `undefined`라 전부 2자리로 폴백한다. 그래서 JPY(100)/KRW가 `8.7292` → **`8.73`**, EUR/USD가 `1.1477` → **`1.15`**로 나온다. `data.json`은 4자리를 갖고 있는데 화면이 버리고 있다.
- **C6 "조원" 자릿수 4종** — 같은 국민연금 AUM이 1자리(`app1:10080`)·로케일 기본(`app1:9550`)·원시값(`app1:10099`)·0자리(`app1:13282`)
- **C7 VKOSPI 무포맷** — `app6:296`이 값을 그대로 문자열화해 데이터에 따라 자릿수가 흔들린다

## 2. 원칙

1. **표기는 지표가 정한다.** 자릿수·단위·부호는 화면이 아니라 레지스트리 행에 적혀 있고, 화면은 그것을 읽어 쓴다.
2. **위젯은 한 벌이다.** 헤더 조각의 순서와 유무가 위젯마다 달라지지 않는다.
3. **값 칸에는 값만.** 단위는 열 머리에, 설명은 값 옆이 아니라 아래 한 줄에.
4. **숨길 거면 지우고, 남길 거면 보여준다.** 조건부 0px 위젯과 `onScreen:false` 지표는 둘 중 하나로 결정한다.

## 3. 개편안

### S1 — 표기 레지스트리와 단일 포매터 (U1) · P0

**레지스트리에 표기 필드를 넣는다.** `scripts/build_indicators.py` 가 생성하는 행에 추가:

| 필드 | 뜻 | 예 |
|---|---|---|
| `unit` | 화면에 쓸 단위(기존, 커버리지 50% → 100%) | `%` · `원` · `달러` · `pt` · `조원` |
| `decimals` | 소수 자릿수(정수 고정) | `kospi` 2 · `usdkrw` 2 · `jpykrw` **4** · `unemployment` 1 |
| `scale` | 값에 곱할 배율과 그때의 단위 | `{by: 1e-12, unit: '조원'}` |
| `sign` | 등락 표기 방식 | `arrow`(▲▼) · `signed`(+/-) · `none` |

**포매터 진입점을 하나로.** `econFmt(id, value, opts)` 를 `js/app0.js` 옆(`js/app1.js` 상단)에 두고,
기존 9개 지표값 포매터는 전부 이 함수에 위임한다. 값 자체를 바꾸지 않는 얇은 층이라 회귀 위험이 낮다.

```js
econFmt('usdkrw', 1372.58)        // '1,372.58'
econFmt('usdkrw', 1372.58, {unit: true})   // '1,372.58원'
econFmt('jpykrw', 8.7292)         // '8.7292'   ← 지금은 '8.73'
econFmt.chg('kospi', 1.65)        // '▲ 1.65%'
```

**C3(실동작 오류)는 P0 안에서 바로 고친다** — `fmt(v, 4)` 처럼 숫자를 kind 자리에 넘기는 11곳이 대상이다.
이건 통일 이전에 **데이터를 버리고 있는 버그**다.

**1440/390 차이** — 없다. 표기는 뷰포트와 무관하다.

### S2 — 위젯 한 벌 (U2) · P0

헤더 조각의 **순서를 고정**한다: `제목 → 출처(다른 화면이 원본일 때) → 신선도 → 별 → 새로고침 → 접기`.
유무 규칙:

| 조각 | 규칙 |
|---|---|
| 제목 | **항상**. 지금 제목 없는 위젯 10개는 제목을 주거나 위젯이 아닌 블록으로 내린다 |
| `data-asof` | 데이터 위젯이면 항상(현행 90% → 100%, G8 이 이미 잰다) |
| 별 | **레지스트리가 아는 지표 제목이면 항상**(현행 9% → 대상 전부). 특권 위젯 9개만 담기는 현 상태를 끝낸다 |
| 새로고침 | 스스로 다시 부를 수 있는 위젯만. 정적 위젯에는 두지 않는다 |
| 접기 | 높이 240px 이상인 위젯만 |

**굵기는 건드리지 않는다**(위 정정 참조 — 600/700은 역할이 다르다). 대신 **`.widget-title` 의 두 역할을 분리**한다:
위젯 제목은 `h3.widget-title`, KPI 라벨은 `.econ-stat__label` 만 남기고 `widget-title` 을 뗀다.
그래야 마킹 코드가 매번 `closest()` 로 KPI 를 걸러내지 않고, 구조 감사도 둘을 섞어 세지 않는다.
여백은 `16px`(모바일 `12px`)이 기본이고 `.pad-14` 는 문서화된 예외로 유지, `0px ×2`·복합 3개만 정리한다.

### S3 — 표 규격 (U4·U5) · P1

- **정렬**: 첫 열(이름) `start`, 나머지 숫자 열 `right`. 이름이 두 칸(코드·이름)이면 두 칸 모두 `start`.
- **단위는 열 머리에** — `현재가(원)` · `등락률(%)` · `거래대금(억)`. 값 칸에는 숫자만(현행 단위셀 비율 0.2~0.75 → 0).

### U9 탭 부품 — 부품이 갈린 게 아니라 **역할 표시가 섞여 있었다** (근본원인)

`.tab-btn` 65개가 `seed-chip` 45 / `seed-tabs` 15 로 갈려 있다는 진단의 원인은 접근성 보강기
(`js/app1.js`)였다. 이 보강기는 `.tab-btn` 묶음이면 **무엇이든** `role=tablist` + `role=tab` +

**동시에** 달고 있었다 — 읽기 도구에는 모순이고, 같은 역할이 두 부품으로 보이는 원인이었다.

규칙을 부품이 스스로 밝힌 대로 정했다.

- **화면 내용을 통째로 바꾸는 2차 탭** = `seed-tabs__trigger` · `role=tab` · `aria-selected`
- **차트·목록의 대상·기간을 고르는 칩** = `seed-chip__root` · 부모는 `role=group` · `aria-pressed`

보강기가 두 경우를 가리게 고치고(칩 묶음은 `aria-pressed` 만 갱신, 값이 같으면 안 쓴다 — G10),
`investorTopTabs` 6개는 컨테이너 6개 중 하나를 보여주는 **진짜 탭**이라 칩→탭 부품으로 바꿨다.

### S23 위젯 이름 줄 — 훑기 목록에 없는 이름 17 → 0

`.widget-title` 은 **두 역할**을 겸하고 있었다(이 겹쳐쓰기는 4차에 CSS 주석으로 이미 적어 뒀다).

- **위젯 이름** — 상자의 제목. 훑기 목록(heading)에 나와야 "이 화면에 무슨 상자가 있나"를 셀 수 있다.

역할을 마크업으로 갈랐다. 위젯 이름은 **`h3` 한 가지**, KPI 카드 라벨은 **`.econ-stat__label`**

### S24 안 보이는 칸의 차트 — 2 → 0

4차의 `econChartLive` 는 "**열린 화면**"만 봤다. 열린 화면 안에도 안 보이는 칸이 있다 —
market 의 금리 탭(`#market-rate`, `display:none`)과 홈의 접힌 비교 칸이 그랬다.
