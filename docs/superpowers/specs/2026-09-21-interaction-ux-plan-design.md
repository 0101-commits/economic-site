# economic-site 조작·전환 개편 기획서 (2026-09-21)

> 앞선 두 기획이 **무엇을 어디에 놓을지**(IA, `2026-09-18-ia-restructure-design.md`)와
> **어떻게 읽히게 할지**(가독성, `2026-09-19-readability-ux-plan-design.md`)를 끝냈다.
> 이 문서는 남은 축 하나, **누르면 무슨 일이 일어나는가**를 다룬다.
> 화면 전환·컴포넌트 상태·조작 피드백. 데스크톱(1440)과 모바일(390) 둘 다.

## 0. 근거 — 무엇을 어떻게 쟀나

Npay증권(네이버)·토스증권과 우리 서비스를 **같은 도구로 같은 조작을 시켜** 비교했다.
정적 캡처 180컷(2026-09-19 아카이브)은 레이아웃·토큰을 봤고, 이번에 더한 것은 **움직임**이다.

| 측정 | 도구 | 표본 | 산출물 |
|---|---|---|---|
| 화면 전환 트레이스 | `scripts/interact.mjs` + `flows/{naver,toss,ecom,login}.json` | 플로우 19벌 · 스텝 106개(성공 99) | `raw/interact/*.json` → `raw/FLOW-DIGEST.md` |
| 조작 인벤토리 | `scripts/controls.mjs` | 화면 31개 · 컨트롤 7,361개 | `raw/controls/*.json` → `raw/CONTROLS-DIGEST.md` |
| 상태(로딩·오류·포커스·실시간) | `scripts/probe-states.mjs` | 사이트 3 × 뷰포트 2 | `raw/states/{naver,toss,ecom}-{d,m}.json` |
| 유휴 DOM 변경 인구조사 | `scripts/probe-idle.mjs` | 3벌 × 20초 | `raw/states/idle-*.json` |
| 실효 타깃 크기 | `scripts/probe-hitarea.mjs` | 3벌 | `raw/states/hit-*.json` |
| 상태 지속(새로고침·공유) | `scripts/probe-persist.mjs` | 케이스 8 | `raw/states/persist.json` |

측정 한계는 그대로 적는다(결론은 이 한계를 넘지 않는다).

- **L1 `settleMs` 는 우리 서비스에서 쓸 수 없다.** MutationObserver 가 300ms 조용해질 때까지 잰 값이고 상한이 6,000ms 인데, 우리는 34/34 스텝이 상한에 붙었다. 이건 "느리다"가 아니라 "쉬지 않는다"는 뜻이고, 그 자체가 §1 D1 이다.
- **L2 `netXhr` 는 스텝당 5개 표본**이다. 조작당 요청 수는 `netCount` 로만 읽는다.
- **L3 스크롤 정책은 트레이스로는 표본 4개**뿐이었다(화면 안 조작 62개 중 58개가 조작 직전 스크롤 0).
  그 4개 중 하나가 도구가 만든 이동이어서(§1 D6) **별도 프로브로 다시 쟀다**(`probe-foldscroll.mjs`).
- **L7 클릭 대상은 라벨로 고른다.** 라벨이 겹치면 도구가 엉뚱한 것을 누른다 — 실제로 D5·D6 두 건이 그렇게 생겼다.
  그래서 이 문서의 진단은 **`hit` 박스를 다시 확인한 것만** 싣는다. 확인 결과 기각된 것도 기각 사실과 함께 남겼다.
- **L4 측정 실패 7건**(`FLOW-DIGEST.md` §8)은 도구가 클릭 대상을 못 찾은 것이지 기능이 없는 게 아니다. 집계에서 뺐다.
- **L5 토스 모바일 웹은 앱 설치 유도 랜딩**이라 UX 비교 대상이 아니다. 모바일 벤치는 네이버 반응형 하나다.
- **L6 `toss-in/` 과 `.profile/` 에는 실제 계좌·쿠키가 들어 있다.** 외부 공유 금지.

## 1. 진단

### D1 — 화면이 한 번도 멈추지 않는다 (P0)

유휴 20초 인구조사(`idle-127-0-0-1-8080--d.json`):

| | 우리 홈 | 네이버 m 홈 | 토스 PC 홈 |
|---|---|---|---|
| DOM 변경 총수 / 초당 | 2,884 / **144.2** | 372 / 18.6 | 4,151 / 207.6 |
| **300ms 이상 조용한 구간** | **0회** | 14회 | 18회 |
| 가장 긴 정적 구간 | **223ms** | 2,011ms | 619ms |
| 최다 변경 요소 | **`button.econ-fav` 2,820건 = 97.8%** | 칩·관심아이콘 120씩 | 가격 텍스트 269+269 |

토스는 우리보다 **44% 더 많이** 바뀌는데도 18번 쉰다. 값이 들어오면 왕창 바꾸고 멈추는 **버스트**다.
우리는 더 적게 바뀌면서 20초 내내 한 번도 쉬지 않는 **상시**다. 게다가 그 변경은 데이터가 아니다 —
`title`·`aria-pressed` 재기입이 1,882건(65.3%), 변경 요소 상위 8개가 전부 즐겨찾기 별이다.

근본원인은 **자기 유발 루프**다. `js/app4.js:220` 의 MutationObserver 가 200ms 디바운스로 마킹 함수
7개(`econMarkHeadings`·`econMarkSources`·`econMarkContext`·`econMarkFavorites`·`econMakeTablesSortable`·
`econMarkScrollables`·`econFoldControls`)를 부르고, 그중 `econMarkFavorites`(`js/app4.js:876`)는 **값이 같아도**
`setAttribute('aria-pressed')`·`title`·`textContent` 를 다시 쓴다. 그 쓰기가 옵저버를 다시 깨운다.

성능보다 먼저 **접근성 문제**다. `aria-pressed` 가 초당 47회 바뀌면 스크린리더는 그때마다 상태 변경을 읽는다.

### D2 — 화면 안에서 한 조작은 주소에 하나도 남지 않는다 (P0)

`FLOW-DIGEST.md` §1: 화면 안 조작(탭·필터·기간·패널·오버레이) 기준.

| | 네이버 | 토스 | 우리 |
|---|---|---|---|
| urlChanged | 9/20 (45%) | 7/23 (30%) | **0/19 (0%)** |
| histDelta 합 | +8 (push형) | +3 / replace형 4건 | **0** |

우리 코드에는 자리가 **이미 있다**. `js/app1.js:729` 의 `ECON_TABS` 가 market·macro·realestate·merlens
4화면의 2차 탭을 `?p=x&t=y` 로 `replaceState` 한다. 그런데 `epc-nav` #5(거시 '주제별' 전환)는
주소에 `t=kr` 을 달고 있으면서도 갱신하지 않았다 — **파라미터 자리는 있고 쓰지 않는다.**
지수 선택·기간 토글·표 정렬·트리거 필터·거시 분류는 애초에 등록돼 있지 않다.

사용자에게 이것이 뜻하는 바: 코스닥 30일 차트를 띄워 링크를 복사해 보내면, 받는 쪽은 코스피 기본 화면을 본다.
새로고침해도 마찬가지고, 뒤로가기는 탭이 아니라 화면 단위로만 돈다.

토스의 반례도 같이 본다: 토스는 replace 만 써서 `tpc-screener` #5·`tpc-home` #6 의 뒤로가기가
**`about:blank` 로 튄다**(사이트 밖). 반면 계좌 탭(`tpc-account` #1~#3)은 push 다. **정책이 조작 종류마다 갈린다** —
베낄 것은 replace 자체가 아니라 그 구분이다.

### D3 — 값이 바뀌어도 화면이 말해주지 않는다 (P1)

실시간 프로브(`raw/states/*.json` §9-1) 와 모션 토큰(§7):

| | 갱신 이벤트 | 애니메이션 동반 | 트랜지션 동반 | 로딩 스켈레톤 |
|---|---|---|---|---|
| 네이버 d/m | 121 / 160 | **27** / 0 | 0 / **80** | **217~220개 / 10종** |
| 토스 d | 401(상한) | 0 | 1 | 57개(해시 클래스) |
| 우리 d/m | 401(상한) | **0 / 0** | 5 / 0 | **49개 / 2종** |

네이버는 값이 바뀌면 `ModulePriceNumber_highlight-fade-up/down | 1s`·`SingleLinePrice_highlight-fade-*`
·`DetailInfo_gapUp | 0.8s` 로 **그 숫자만 잠깐 빛난다**. 우리 34스텝 전체에서 `anim:` 토큰은 상위 5위에 한 번도 못 들었다.
스켈레톤은 `econ-await-shimmer` 한 종류가 위젯 49곳에 깔려 있을 뿐, 표·차트·KPI 가 각자의 모양으로 기다리지 않는다.

### D4 — 누를 것이 작다 (P1)

`probe-hitarea.mjs` 는 박스가 아니라 `elementFromPoint` 로 **실제로 눌리는 범위**를 잰다(`::after` 확장 반영).

| | 실효 min 중앙값 | 실효 <24px | 실효 <44px |
|---|---|---|---|
| 우리 모바일 | **20px** | **56.4%** | 69.2% |
| 우리 데스크톱 | 44px | 28.1% | 42.2% |
| 네이버 모바일 | 44px | **17.9%** | 50.0% |

우리 모바일에서 24px 을 못 넘는 대표 사례는 **티커 항목 전체**다(`USD/KRW 1,378.06 ▼ 0.57%` 192×20 → 확장 없음).
데스크톱도 지표 카드의 숫자 줄이 20px 높이 그대로다. 박스 기준 집계(`CONTROLS-DIGEST.md` §4)에서도
min<24px 이 우리 데스크톱 37.4% · 모바일 33.7% 로 토스 PC 2.8% · 네이버 PC 16.6% 와 벌어진다.

### D5 — 정렬은 되는데, 정렬할 수 있다는 사실이 화면에 없다 (P1)

먼저 정정: `FLOW-DIGEST.md` §6 은 `epc-widget` #5 를 "표 머리를 누르려다 전역 검색이 열렸다"로 적었다.
`hit` 박스를 보면 `[1038,28,48,48]` — **헤더 우상단의 검색 버튼**이다. 위젯 머리글이 아니라
내 플로우가 대상을 `지표` 로 지정해 도구가 `지표 검색` 을 고른 것이다. **표적 겹침은 사실이 아니다.**

대신 직접 쟀다(`scripts/probe-sort.mjs`):

| 화면 | 표 | 정렬 가능 표 | `aria-sort` 붙은 `th` | 정렬 화살표 | `::after` 표식 | cursor | tabindex |
|---|---|---|---|---|---|---|---|
| investor | 27 | 12 | 55 | **0개** | `none` | pointer | 0 |
| equity | 27 | 13 | 58 | **0개** | `none` | pointer | 0 |
| macro | 27 | 11 | 50 | **0개** | `none` | pointer | 0 |
| merlens | 32 | 15 | 93 | **0개** | `none` | pointer | 0 |

동작은 정상이다(`지수` 열 클릭 → `aria-sort=ascending`, 행 순서 실제 변경 확인).
문제는 **50~93개의 열 머리 중 어느 것이 눌리는지 화면이 말하지 않는다**는 것이다.
토스는 라벨 자체가 `정렬 없음` / `내림차순 정렬됨` 이다(`CONTROLS-DIGEST.md` §5 최빈 라벨).

### D6 — (기각) 위젯 펼치기의 스크롤 초기화는 우리 문제가 아니었다

1차 트레이스에서 `em-nav` #4(접힌 위젯 펼치기)가 document 스크롤 **1,200 → 0** 으로 잡혔다.
근거를 다시 보니 그 스텝의 `hit` 박스가 `y=-1075` — **화면 위쪽 밖**이다. 클릭 도구가 대상을 보이게 하려고
스스로 위로 스크롤한 것이고, 제품이 튕긴 게 아니다.

화면 안에 보이는 토글만 눌러 다시 쟀다(`scripts/probe-foldscroll.mjs`, `raw/states/foldscroll-*.json`):

| 뷰포트 | 측정 | 스크롤 이동 |
|---|---|---|
| 390 | 3건 (900/1,183/1,183) | **0건** (Δ0·Δ0·Δ0) |
| 1440 | 3건 (900/1,800/2,329) | **0건** (Δ0·Δ0·Δ0) |

`showPage`(`js/app1.js:1172`)만 맨 위로 스크롤하고, 접기/펼치기는 스크롤을 건드리지 않는다 — **현행이 옳다.**
남는 것은 제품 결함이 아니라 관성 문제다: 위쪽 위젯을 접으면 아래 내용이 그만큼 올라온다(`scrollY` 는 그대로).
지금 규모에서는 개편 대상이 아니라고 본다.

### D7 — 잘못된 주소가 조용히 홈이 된다 (P2)

`?p=nosuchpage` → status 200, 본문 3,249자, **오류 문구 없음 · 복구 버튼 없음**. 대시보드가 그냥 뜬다.
벤치 6벌 중 오류를 말해준 것은 토스 모바일 하나뿐이다("지원하지 않거나 상장 폐지된 주식이에요" + `확인`).
네이버도 홈으로 흘려보낸다 — 그래서 이건 벤치를 베끼는 항목이 아니라 **우리가 더 잘할 수 있는 자리**다.

같은 성격의 침묵이 하나 더 있다. 우리 플로우 6벌 모두 **콘솔 오류 10건**(외부 프록시 403/503/530/410)이 잡혔다.
다른 4개 서비스는 최대 1건이다. 사용자 눈에는 위젯이 그냥 비어 보인다.

### D8 — 라벨이 1회용이다 (P2)

`CONTROLS-DIGEST.md` §5.

| | 고유 라벨 / 전체 | 빈 라벨(아이콘 전용) | 11자 이상 |
|---|---|---|---|
| 우리 데스크톱 | **629 / 1,140** | 0% | **42.8%** |
| 우리 모바일 | 165 / 282 | 0% | **49.3%** |
| 네이버 모바일 | 337 / 970 | 2.2% | 29.9% |
| 토스 PC | 1,228 / 3,168 | 26.3% | 14.3% |

벤치의 동사는 짧고 **반복된다** — `더보기`·`전체보기`·`자세히 보기`·`관심종목 설정하기`·`확인`·`닫기`.
한 번 배우면 어디서나 같은 말이다. 우리는 `근거 보기` 계열만 60가지가 넘고(`황산 → 구리·비철 근거 보기` …),
접기 버튼의 `aria-label` 이 위젯 제목 전체를 읽는다(`접기: 거래대금 Top20 시장 전체 · 종목 클릭 → 종목`).

그리고 우리 데스크톱 **최빈 라벨 1·3·4위가 `OW`(33) · `N`(29) · `UW`(18)** 다. 해독 키가 화면에 없다.

### D8-b — 표기가 갈리고, 라벨이 본문을 통째로 읽는다 (P2, D8 연장)

- **같은 동작의 표기가 셋**: `새로고침` · `↻ 새로고침` · `refresh 새로고침` 가 한 서비스 안에 공존한다.
- **벤치에 있고 우리에 없는 말**: `자세히 보기` · `전체보기`. 벤치의 "보기" 계열은 목적어를 앞에 붙여 늘린다
  (`순위 자세히 보기`·`항목 더보기`·`차트 크게보기`) — 어미는 같고 앞만 바뀐다.
- **11자 이상 라벨이 우리 데스크톱 42.8% · 모바일 49.3%**(토스 14.3%). 원인은 `aria-label` 에 위젯 본문을 넣은 것이다
  (`# 종목 등락 거래대금 1 삼성전자 +3.54% 2.4조 …`).

### D9 — "선택됨"이 너무 많고, 굵기로는 구분되지 않는다 (P2)

| | sel=true 비율 | fw 중앙값 sel / unsel | fw≥600 비율 sel / unsel |
|---|---|---|---|
| 우리 데스크톱 | **29.8%** | 500 / 500 | 23.2% / 5.8% |
| 네이버 PC | 7.7% | 400 / 400 | 26.3% / 2.1% |
| 네이버 모바일 | 15.8% | **700 / 400** | 54.9% / 6% |

컨트롤 셋 중 하나가 늘 "켜짐"으로 보이는데, 정작 굵기는 선택/비선택이 같다.

### D10 — 한 번 누를 때 여섯 속성이 동시에 움직인다 (P3)

모션 토큰 합계(§7): 우리 최빈이
`background-color, color, border-color, box-shadow, outline-color, scale | 0.15s ×6` — **요소 4,352개**.
토스 최빈은 `box-shadow, background, color | 0.2s, 0.2s, 0.1s`(950), 네이버는 `all | 0.2s`(166).
duration 은 우리가 가장 짧고(0.15s/0.1s) easing 은 단일이라 **토큰 일관성 자체는 세 서비스 중 가장 깔끔하다** —
문제는 `scale` 과 `padding` 까지 전환에 물려 누를 때 레이아웃이 미세하게 흔들린다는 것이다.

### D11 — 화면을 옮기는 컨트롤의 3분의 2가 링크가 아니다 (P2)

밀도 자체는 문제가 아니다. 컨트롤 실측 연장 1,000px당 **우리 데스크톱 72.4 · 네이버 PC 76.0**(토스 PC 185.2) —
네이버와 거의 같다. 갈리는 것은 **구성**이다(`CONTROLS-DIGEST.md` §2).

| | 링크(`a[href]`) | 버튼 |
|---|---|---|
| 네이버 PC / 모바일 | 33.7% / 35.6% | 15.6% / 5.1% |
| 토스 PC | 9% | 15.3% |
| **우리 데스크톱 / 모바일** | **16.1% / 17.0%** | **50.4% / 47.5%** |

비율만으로는 판단할 수 없어(위젯 접기·새로고침·별은 당연히 버튼이다) **화면을 옮기는 컨트롤만** 따로 셌다
(`[data-goto]`·`[data-page]`·`showPage`/`gotoCanonical`/`econNav`/`tickerClick` 핸들러, 1440 실측):

| 화면 | 이동 컨트롤 | `<a href>` | **링크가 아닌 것** |
|---|---|---|---|
| 홈 | 40 | 13 | **27** (티커 항목 전부) |
| 주식시장 | 23 | 13 | **10** |

사이드바와 하단 탭바는 이미 `<a href="?p=…">` 다(`index.html:2447`·`2571`). 남은 것은 **티커·KPI·표 행·레일 항목**이고,
이들은 버튼이라 **새 탭·주소 복사·가운데 클릭이 되지 않는다**. D2 와 같은 뿌리다.

덧붙여 헤딩 위계가 **H2 를 건너뛴다** — 우리 H1 5 / **H2 2** / H3 28, 네이버는 H2 46 / H3 10.
(토스는 6화면 통틀어 헤딩 1개다 — 이건 벤치가 나쁜 쪽이라 베끼지 않는다.)

## 2. 개편 원칙

1. **주소가 화면 상태다.** 사람이 다시 볼 만한 상태는 주소에 있고, 순간적인 UI 는 주소에 없다.
2. **움직임은 데이터일 때만.** 값이 바뀌면 보이게 하고, 값이 안 바뀌면 화면은 쉰다.
3. **한 조작 = 한 가지 일.** 표적이 겹치지 않고, 스크롤은 제자리에 있고, 무슨 일이 일어났는지 화면이 말한다.
4. **말은 사전에서 꺼내 쓴다.** 동사는 열두 개, 약어는 금지, `aria-label` 은 제목까지만.

## 3. 개편안

각 항목에 1440(데스크톱)과 390(모바일)의 차이를 적는다.

### C1 — 조용한 화면 (D1)

**무엇을 바꾸나**

1. **마킹 함수를 멱등으로.** `econMarkFavorites`·`econMarkHeadings`·`econMarkSources`·`econMarkContext`·
   `econMarkScrollables` 는 값을 쓰기 전에 현재 값과 비교하고, 같으면 아무것도 하지 않는다.
   ```js
   var want = r ? '★' : '☆';
   if (n.textContent !== want) n.textContent = want;
   if (n.getAttribute('aria-pressed') !== String(r)) n.setAttribute('aria-pressed', String(r));
   ```
2. **옵저버 자기 유발 차단.** 디바운스 콜백 전체를 `mo.disconnect()` → 마킹 → `mo.observe()` 로 감싼다.
   멱등화만으로도 대부분 잡히지만, 새 마킹 함수가 추가돼도 루프가 되살아나지 않게 하는 안전장치다.
3. **관찰 범위 축소.** `attributeFilter` 를 두지 않은 `subtree+attributes` 관찰은 자기 쓰기를 전부 되받는다.
   `childList` + `characterData` 만 보고 속성은 보지 않는다(마킹이 필요한 신호는 노드 추가/텍스트 변경이다).

**사용자가 느끼는 것** — 화면이 가만히 있는다. 스크린리더가 별 버튼 상태를 계속 읽지 않는다.
저사양 기기·배터리에서 체감이 큰 자리다(모바일).

**1440/390 차이** — 없다. 공통 수정이다.

### C2 — 주소가 화면 상태다 (D2)

**뷰 상태 레지스트리로 확장.** `ECON_TABS`(`js/app1.js:729`)를 `ECON_VIEW` 로 넓혀, 탭 말고도
"다시 볼 만한 상태"를 등록한다. 값은 짧은 키 하나씩.

| 파라미터 | 뜻 | 대상 화면 | 예 |
|---|---|---|---|
| `t` | 2차 탭 (현행 유지) | market·macro·realestate·merlens | `?p=market&t=bond` |
| `v` | 같은 화면의 보기 전환 | macro 국가별/주제별, merlens 보드/글찾기 | `?p=macro&v=topic` |
| `f` | 필터·분류 선택 | equity 지수, macro 분류, merlens 트리거 상태, calendar 국가·중요도 | `?p=equity&f=kosdaq` |
| `r` | 기간 | equity·market 차트 기간 | `?p=equity&r=1m` |
| `s` | 정렬 | 정렬 가능한 표(열 인덱스+방향) | `?p=investor&s=3d` |

**적용 규칙 3줄** (조작 종류로 갈린다 — 토스처럼 갈리되, 토스의 뒤로가기 함정은 피한다):

- **화면 이동** = `pushState` (현행 유지, 이미 7/7 이 그렇다).
- **보기 전환**(탭·필터·기간·정렬) = `replaceState`. 주소는 갱신되고 히스토리는 쌓지 않는다.
  같은 화면에서 필터를 열 번 만지고 뒤로가기를 눌렀을 때 이전 화면으로 가야지, 필터 열 칸을 거슬러 가면 안 된다.
- **순간 UI**(오버레이·MY 레일·위젯 접기·사이드바) = 주소에 넣지 않는다. 위젯 접힘만 `localStorage` 에 남긴다.

**되살리는 쪽**도 같은 레지스트리를 쓴다. `econApplyTabFromUrl` 을 `econApplyViewFromUrl` 로 바꿔
`t/v/f/r/s` 를 순서대로 적용하고, 유효하지 않은 값은 조용히 무시한다(현행 `valid` 배열 방식 유지).

**사용자가 느끼는 것** — 지금 보는 화면을 그대로 링크로 보낼 수 있다. 새로고침해도 보던 자리다.
뒤로가기가 화면 단위로 예측 가능하게 돈다.

**1440/390 차이** — 없다(주소는 공통). 다만 모바일은 하단 탭바(`.econ-bottom-nav`)가 1차 이동을 담당하므로,
`econNavGroup` 도 같은 push 규칙을 따르는지 확인한다.

### C3 — 값이 바뀌면 보이게 (D3)

1. **갱신 하이라이트.** 숫자를 다시 그리는 자리(`applyWidgetFreshChips` 가 아는 위젯, KPI, 티커, 표 셀)에서
   값이 실제로 달라졌을 때만 `.econ-flash-up` / `.econ-flash-dn` 를 0.8s 붙였다 뗀다.
   색은 `--c-up`/`--c-down`, 배경 8% 틴트 → 투명. `prefers-reduced-motion` 이면 클래스 자체를 붙이지 않는다.
   (네이버 `ModulePriceNumber_highlight-fade-up | 1s` 과 같은 장치. C1 이 끝나야 의미가 있다 —
   지금은 안 바뀐 값도 계속 다시 써서 온 화면이 깜빡일 것이다.)
2. **기다리는 모양을 세 종류로.** 현재 `econ-await` 한 종류(49곳)를 표(행 스켈레톤)·차트(면 스켈레톤)·
   KPI(숫자 블록 스켈레톤)로 나눈다. 네이버가 10종을 쓰는 이유는 **무엇이 오고 있는지**를 모양으로 알리기 위해서다.
3. **실패도 모양이 있다.** 프록시 403/503 으로 못 채운 위젯은 빈 채로 두지 않고
   "불러오지 못했습니다 · 다시 시도" 한 줄 + 버튼. 콘솔 10건이 화면에서는 침묵인 현 상태를 끝낸다.

**1440/390 차이** — 모바일은 스켈레톤 행 수를 3으로 제한(데스크톱 5~8). 하이라이트는 동일.

### C4 — 누를 것을 키운다 (D4)

- **모바일 하한 44px, 데스크톱 하한 32px(실효 기준).** 박스가 아니라 `::after` 확장 포함 실효값이 기준이다.
- 티커 항목(`.ticker-item`)은 세로 패딩으로 실효 44px 을 만든다 — 현재 20px.
- 지표 카드·목록의 숫자 줄처럼 "행 전체가 링크"인 자리는 행 높이를 32/44 로 올리고, 텍스트만 링크로 두지 않는다.
- `.econ-fav`·`.econ-src`·`.w-fresh-chip` 의 `::after` 확장 관행(`index.html:1650`)을 **표준 유틸 클래스**로 뽑아
  새로 만드는 작은 컨트롤이 같은 확장을 상속하게 한다.

**1440/390 차이** — 하한값 자체가 다르다(32 / 44). coarse 포인터에서만 확장하는 현행 규칙은 유지한다.

### C5 — 정렬을 보이게 (D5)

`econMakeTablesSortable`(`js/app4.js`)이 `aria-sort` 를 붙일 때 시각 표식도 같이 붙인다.

- 정렬 가능한 `th` 는 옅은 `⇅`, 정렬 중인 열은 `▲`/`▼`. 아이콘은 글자가 아니라 `::after` 로 넣어
  셀 텍스트(=G6 자릿수 검사 대상)를 오염시키지 않는다.
- 정렬 중인 열은 머리글 굵기 700(C9 의 선택 규칙과 같은 쌍).
- `aria-sort` 값은 현행 유지(`none`/`ascending`/`descending`) — 보조기기 쪽은 이미 맞다.

**1440/390 차이** — 모바일은 표가 가로 스크롤되므로(`econ-scrollhint`) 아이콘이 열 폭을 더 먹지 않게
`::after` 를 절대 위치로 겹쳐 놓는다.

### C6 — (없음) D6 이 기각되어 이 자리는 비어 있다

번호를 당기지 않는 이유는, 이후 문서·커밋에서 C7~C10 을 가리킨 말이 어긋나지 않게 하기 위해서다.

### C7 — 모르는 주소·실패에 말을 건다 (D7)

- 폴백 지점은 `js/app1.js:1160` 한 줄이다 — `if(!document.getElementById('page-'+id)) id = 'dashboard';`.
  여기서 **폴백했다는 사실을 들고** 나와, 대시보드를 그냥 렌더하지 않고 상단에
  "'nosuchpage' 화면이 없습니다 — 대시보드로 왔습니다" + `전체 화면 보기` 버튼을 띄운다(3초 후 자동 사라짐 없음).
- `&t=`/`&f=` 가 유효 목록 밖이면 조용히 무시(현행)하되, 콘솔에 남긴다.
- 위젯 데이터 실패는 C3-3 과 같은 장치.

### C8 — 말 사전 (D8)

**동사 12개로 고정.** 다른 말은 새로 만들지 않는다.

`더 보기` · `접기` · `펼치기` · `새로고침` · `전체` · `초기화` · `적용` · `원본 화면` · `근거` · `공유` · `편집` · `닫기`

- `근거 보기` 60여 종은 버튼 라벨을 `근거` 로 통일하고, 무엇의 근거인지는 **버튼이 있는 자리**(행·칩)가 말한다.
  `aria-label` 은 `근거: <지표명>` 까지. 지금처럼 경로 전체(`황산 → 구리·비철 근거 보기`)를 읽지 않는다.
- 접기/펼치기 `aria-label` 은 `접기: <위젯 제목>` 까지, 부제·설명은 넣지 않는다.
- **약어 금지.** `OW`/`UW`/`N` → `비중확대`/`비중축소`/`중립`. 좁은 칸이면 `확대`/`축소`/`중립`.
  (이 규칙이 D8 의 최빈 라벨 1·3·4위를 지운다.)
- 이모지를 라벨에서 뺀다 — `🌍 국가별`·`📊 주제별`·`🧭 보드`·`📝 글 찾기`·`📅 오늘` 이 남아 있다
  (2026-09-18 개편에서 본문 이모지 26개를 지웠지만 컨트롤 라벨은 빠졌다).
- **한 동작에 한 표기.** `새로고침` 하나로 통일한다(`↻ 새로고침`·`refresh 새로고침` 폐기 — 아이콘은 라벨 밖).
- **"보기" 계열은 어미를 고정하고 앞만 바꾼다** — `자세히 보기`·`전체 보기`를 사전에 넣고,
  필요하면 목적어를 앞에 붙인다(`순위 자세히 보기`). 새 어미를 만들지 않는다.
- **`aria-label` 에 위젯 본문을 넣지 않는다** — 11자 이상 라벨 42.8%(모바일 49.3%)의 원인이다. 제목까지만.

### C9 — 선택은 한 쌍으로 (D9)

선택 표시는 **배경 + 굵기 700** 한 쌍으로 통일한다(네이버 모바일 방식: 700/400).
`active` 클래스를 "지금 고른 것"에만 쓰고, 상태 표시가 아닌 곳(항상 켜진 유틸 버튼 등)에서 뗀다.
목표는 sel=true 비율을 29.8% → 15% 이하로 내리는 것이다 — 숫자 자체가 목적이 아니라,
"켜짐"이 절반 가까이 되면 그게 정보가 아니게 되기 때문이다.

### C10 — (기각) 전환 6속성은 우리 CSS 가 아니었다

구현하려고 출처를 짚어보니 `background-color, color, border-color, box-shadow, outline-color, scale | 0.15s ×6`
은 **벤더 파일 `css/seed/seed.css`** 의 recipe(예: 1300·1687·1864행)에서 나온다. 우리 스타일시트에는
`transition` 에 `scale` 을 건 자리가 없다.

그래서 기각한다. 근거 셋:
- **손대면 사라진다** — `scripts/vendor_seed_css.py` 가 다음 갱신에서 덮는다.
- **의도된 피드백이다** — `--seed-duration-pressed-scale` 은 SEED 의 '눌림' 표현이다. 빼면 디자인 시스템과 어긋난다.
- **실측상 해롭지 않다** — duration 0.15s 단일, easing 단일이다(`FLOW-DIGEST.md` §7 은 이 점을 "세 서비스 중 가장 깔끔"으로 적었다).
  D10 이 지적한 것은 '속성 수'뿐이고, 그 수는 SEED 의 선택이다.

### C11 — 옮기는 것은 링크로 (D11)

- **다른 화면으로 가는 컨트롤은 `<a href="?p=…">`.** 티커 항목(`tickerClick`)·홈 KPI·표의 대표 칸·MY 레일 항목이 대상이다.
  기존 핸들러는 그대로 두고 `href` 를 더한 뒤 `onclick` 이 `return false` 로 기본 이동을 막는 현행 방식을 따른다
  (사이드바 `econNav` 가 이미 그렇게 동작한다). 새 탭·주소 복사·가운데 클릭이 따라온다.
- **버튼 안에 링크를 넣지 않는다** — 홈 KPI 는 `<button>` 이라 안에 `<a>` 를 넣으면 컨트롤 중첩이다(gridcheck 가 잡는다).
  KPI 는 껍데기를 `<a>` 로 바꾸고 내부는 순수 표시로 둔다.
- **헤딩 H2 복원** — 화면 제목(H1) → 섹션(H2) → 위젯(H3) 세 단. 지금 H2 가 2개뿐이라 `.page-toc` 목차가
  위젯 제목(H3)에 바로 붙는다.

**1440/390 차이** — 링크화는 공통. H2 복원은 목차와 짝이라 모바일에서 효과가 더 크다.

**구현하며 드러난 사실 넷**(기획서의 진단을 정정한다)

1. **옵저버는 원래부터 속성을 보지 않았다.** `js/app4.js` 의 MutationObserver 는 `{childList, subtree}` 다.
   루프의 진짜 고리는 `btn.textContent = …` 였다 — 같은 값을 다시 써도 텍스트 노드가 교체되고, 그게 childList
   변경이라 옵저버가 깨어난다. 그래서 C1-3(관찰 범위 축소)은 할 일이 없었고, 멱등화 한 가지로 끝났다.
2. **정렬 표식은 '없던' 게 아니라 '깨져 있었다'.** `th[aria-sort="ascending"]::after` 의 값이 CSS 이스케이프
   `\2191`(↑)이었는데 8진 이스케이프로 해석돼 제어문자 + `"91"` 이 화면에 찍히고 있었다. 정렬하면 열 머리에
   `91`/`93` 이 보였다. 문자는 리터럴로 적어야 한다.
3. **없는 주소의 진입점이 두 곳이다.** `showPage` 의 폴백(`js/app1.js`)만 고치면 `?p=nosuchpage` 는 여전히
   조용하다 — `js/app4.js` 의 load 핸들러가 화이트리스트 밖 값을 만나면 `showPage` 를 아예 부르지 않는다.
4. **티커 타깃은 위로 넓힐 수 없다.** `::after { inset: -12px }` 로 띠 밖까지 넓혀도 위쪽은 앱바가 클릭을
   가져간다(실측: 확장 전후 모두 20px). 띠 높이 32px 안을 패딩으로 채우는 것이 답이다 — 띠를 키우면 M8(첫 데이터
   420px)이 밀린다.
