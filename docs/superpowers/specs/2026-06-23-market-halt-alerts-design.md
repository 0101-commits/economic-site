# 시장중단 경보 (서킷브레이커·사이드카) — 설계 스펙

- 날짜: 2026-06-23
- 대상 repo: `economic-site` (한국 경제 대시보드)
- 요청: 서킷브레이커·사이드카 발동 시 ① 사이트 상단에 경고/알림(사유·발동·재개시각) ② 해당 메뉴탭 경고 표시 ③ 카카오톡 알림.

## 1. 목표 / 비목표

**목표**
- 한국 시장 전체 사건인 **서킷브레이커(CB)** 와 **사이드카** 발동을 장중 자동 감지.
- 발동 시 전 페이지 상단 경고 배너 + '국내증시' 메뉴탭 배지 표시. 배너에 **사유·발동시각·재개(해제)예정시각** 명시.
- 과거 발동 **이력 목록** 보관(국내증시 페이지).
- **신규 발동/해제** 시 카카오톡 알림 발송.

**비목표 (YAGNI)**
- 종목별 VI(변동성완화장치) — 너무 잦고 요청 범위 밖. 제외.
- 미국/해외 시장 서킷브레이커 — 이번 범위 아님(추후 확장 가능하게 스키마만 일반형 유지).
- 실시간(초단위) 감지 — 무료 한계상 불가. 사용자 승인: 최선노력 ~10~15분 지연 허용.

## 2. 감지 규칙 (정확한 임계치)

### 서킷브레이커 (하락 전용 — 한국은 상승 CB 없음)
| 단계 | 조건(전일종가 대비, 1분 지속) | 조치 |
|------|------------------------------|------|
| 1단계 | 지수 −8% 이상 하락 | 20분 전 종목 매매중단 + 이후 10분 단일가(동시호가) → 재개 |
| 2단계 | −15% 이상 하락 **및** 1단계 대비 추가 −1%p | 20분 중단 + 10분 동시호가 |
| 3단계 | −20% 이상 하락 **및** 2단계 대비 추가 −1%p | **당일 장 종료** |
- 각 단계 1일 1회. 1·2단계는 14:50 이후 미발동(3단계는 시간 무관).

### 사이드카 (상승=매수, 하락=매도 양방향)
| 시장 | 조건(전일 대비, 1분 지속) | 조치 |
|------|---------------------------|------|
| 코스피 | KOSPI200 선물 ±5% | 프로그램매매 호가효력 5분 정지 → 자동해제 |
| 코스닥 | 코스닥150 선물 ±6% **및** 현물 ±3% | 5분 정지 → 자동해제 |
- 1일 1회. 장 종료 40분 전(15:20) 이후 미발동.

### 감지 2겹 (정직성 — 날조 금지)
- **1겹 (확실·무의존)**: 파이프라인이 이미 수집하는 KOSPI/KOSDAQ 지수 등락률로 **CB 단계 추정**. 추가 소스 0, 항상 동작. 한계: 10분 스냅샷이라 발동 후 재개돼 등락률이 회복되면 놓칠 수 있음. → 발동 추정 시 `marketHalts.active` 에 기록하되, 다음 스냅샷에서 임계 미만이면 규칙상 재개시각까지 유지 후 history 이동.
- **2겹 (최선노력 스크레이프)**: KRX 보도자료/네이버 증시 공지를 읽어 ① CB 확정 + **정확한 발동·해제 시각·사유** ② **사이드카 포착**(1겹은 선물 데이터 없어 불가).
- 둘 중 하나라도 잡히면 발동 처리. 시각 미상이면 위 규칙으로 `resumeAt` 계산.
- **소스 우선순위**: 스크레이프(정확) > 지수추정(폴백). 같은 사건이면 스크레이프 값으로 갱신.

### 감지 소스 검증 (구현 1순위 작업)
- 실제 발동이 드물어 **실시간 테스트 불가**. 따라서:
  - 구현 첫 단계로 KRX/네이버의 발동현황·보도자료 페이지에서 **안정적으로 파싱 가능한 엔드포인트를 확정**한다.
  - 확정 실패 시: 1겹(지수추정) + 뉴스 검색("서킷브레이커 발동"/"사이드카 발동", 당일·최근만) 폴백을 쓰고, **스펙/주석에 한계를 정직히 명시**한다(가짜 데이터·미검증 소스 금지).
  - 기존 코드의 KRX 호출 인프라(`KRX_BASE = data-dbg.krx.co.kr/svc/apis`, `KRX_ID`/`KRX_PW`)와 네이버 스크레이프(Worker/공개프록시 폴백) 패턴을 재사용.

## 3. 아키텍처 / 데이터 흐름

```
fetch_data.py (fetch-data.yml, 장중 10분 주기)
  └─ detect_market_halts()  ──▶  data.json.marketHalts { active[], history[], asOf, stale }
                                       │
fetch-data.yml 다음 스텝               ├─▶ index.html 가 data.json 읽음
  └─ check_halts.py                    │     ├─ 전 페이지 상단 경고 배너 (active)
       active vs halts_state.json      │     ├─ '국내증시' 메뉴탭 배지 (active)
       → 신규 발동/해제만 카톡 발송      │     └─ 국내증시 페이지 이력표 (history)
       (send_kakao_digest 재사용)       │
                                       └─▶ validate_data.py 가 marketHalts 형태 검증(하드 게이트)
```

### 변경/신규 파일
| 파일 | 작업 |
|------|------|
| `scripts/fetch_data.py` | `detect_market_halts()` 추가 → `data["marketHalts"]` 기록. 부분 실패 시 이전 값 보존(기존 관행). |
| `scripts/check_halts.py` | **신규**. `check_alerts.py` 구조 복제: marketHalts.active 평가 → 신규/해제 카톡. 테스트 발송 모드 포함. |
| `halts_state.json` | **신규**. 발송 이력(도배방지). 워크플로가 커밋해 런 간 보존. |
| `scripts/validate_data.py` | `marketHalts` 스키마 검증 추가(존재/형태). |
| `.github/workflows/fetch-data.yml` | `fetch_data.py` 다음에 `check_halts.py` 실행 스텝 추가. `halts_state.json` 커밋 포함. |
| `index.html` | 상단 배너 + 메뉴탭 배지 + 국내증시 이력표 + 렌더 로직(인라인 CSS/JS). |
| `CLAUDE.md` | 새 스크립트/워크플로 스텝/스키마 문서 한 줄 추가. |

## 4. data.json 스키마

```json
"marketHalts": {
  "active": [
    {
      "id": "circuit-KOSPI-1-20260623",
      "type": "circuit",           // "circuit" | "sidecar"
      "market": "KOSPI",           // "KOSPI" | "KOSDAQ"
      "stage": 1,                  // CB 1/2/3, 사이드카는 null
      "direction": "down",         // CB=항상 down, 사이드카= up|down
      "reason": "코스피 지수 -8.1%",
      "triggeredAt": "2026-06-23T14:31:00+09:00",
      "resumeAt":   "2026-06-23T14:51:00+09:00",  // 규칙계산 또는 공지값. CB3단계=당일종료(null+endOfDay)
      "endOfDay": false,
      "source": "index"            // "index"(추정) | "krx" | "naver" | "news"
    }
  ],
  "history": [ /* active 와 동일 형태, 최근 30건, 최신순 */ ],
  "asOf": "2026-06-23T14:40:00+09:00",
  "stale": false
}
```
- `id` = 사건 고유키(중복방지/상태매칭용). `{type}-{market}-{stage}-{YYYYMMDD}`.
- active 비었으면 `[]`(배너 숨김). 사건 종료 시 active→history 이동.

## 5. 프론트엔드 (index.html)

- **상단 경고 배너**: 전 페이지 상단 고정(showPage 와 무관, body 최상단). active 있으면 표시.
  - 색: 서킷=빨강 계열, 사이드카=주황 계열. 단계별 강도.
  - 문구 예: `🔴 코스피 서킷브레이커 1단계 발동 — 전일比 -8.1% · 14:31 매매중단 → 14:51 재개예정` + 재개까지 카운트다운(JS). CB3단계는 "당일 장 종료".
  - 여러 건 동시(코스피+코스닥) 가능 → 스택 표시.
  - 닫기(X) 가능하되 active 지속 중 새로고침 시 재표시(localStorage 로 "이 사건 닫음" 기억, 사건 id 기준).
- **메뉴탭 배지**: '국내증시' 탭에 빨간 점/숫자. active 개수.
- **이력표**: 국내증시 페이지 하단 카드. 컬럼: 일시 · 종류 · 시장 · 단계/방향 · 사유 · 중단~재개. 최신순, history 기반.
- 기존 카드/배지 CSS·테마색(getThemeColors) 재사용. **CSP 준수(인라인만, eval 없음, Tailwind CDN 금지)**.

## 6. 카카오톡 (`check_halts.py`)

- `check_alerts.py` 구조 복제:
  - `send_kakao_digest` 모듈의 `refresh_access_token`/`get_friends`/`send_memo` 재사용.
  - `marketHalts.active` 의 각 사건을 `halts_state.json` 과 비교 → **신규 발동** 또는 **해제(active→사라짐)** 만 발송.
  - 도배방지: 사건 `id` 당 발동 1회 + 해제 1회. state 에 `{id: {sent, resolvedSent, ts}}`.
  - 테스트 발송 모드(`repository_dispatch`) — 가짜 사건으로 경로 검증, state 미갱신.
- 메시지 예:
  ```
  🔴 [시장경보] 코스피 서킷브레이커 1단계 발동
  사유: 지수 전일比 -8.1%
  매매중단 14:31 → 재개예정 14:51
  ※ 최대 15분 지연 가능 · 정확한 시각은 거래소/증권사 앱 확인
  ```
- 해제 메시지: `🟢 [시장경보 해제] 코스피 서킷브레이커 — 14:51 거래 재개`.
- 발송 경로 = 기존 `KAKAO_REST_API_KEY`/`KAKAO_REFRESH_TOKEN` secrets. 수신 = 기존과 동일(친구 또는 나와의 채팅).

## 7. 워크플로 (`fetch-data.yml`)

- 흐름: `fetch_data.py`(data.json 작성) → `validate_data.py`(하드 게이트) → **`check_halts.py`(신규 스텝)** → 커밋.
- `check_halts.py` 는 게이트 통과 후 실행: 로컬 data.json 을 읽어 카톡 발송 + `halts_state.json` 작성(KAKAO secrets env 주입). data.json 푸시 전 로컬 파일 기준이므로 커밋 여부와 무관하게 동작.
- `halts_state.json` 을 data.json 커밋과 함께 푸시(기존 5-retry 푸시 루프에 포함해 런 간 도배방지 이력 보존).
- CB/사이드카는 한국 장중에만 발생 → 기존 10분 주기(장중) 가 적합. 별도 cron 불필요.

## 8. 검증 (완료 기준)

1. `python scripts/validate_data.py` — marketHalts 포함 통과.
2. headless Chrome 로 index.html 렌더 → 콘솔 0 에러(기존 관행).
3. 가짜 `marketHalts.active` 주입한 data.json 으로:
   - 상단 배너 표시 + 카운트다운 동작.
   - '국내증시' 탭 배지 표시.
   - 이력표 렌더.
   - `check_halts.py` 테스트 발송 → 카톡 수신 확인.
4. active 비운 상태 → 배너/배지 사라짐, 이력만 남음.
5. CB 3단계(당일종료)·사이드카 상승/하락 각 케이스 문구 확인.

## 9. 리스크 / 오픈 이슈

- **감지 소스 안정성**: 스크레이프 대상(KRX/네이버) 마크업·엔드포인트 변경 위험. → 1겹(지수추정) 폴백 항상 유지 + 소스 실패 로깅. 미검증 소스로 가짜 발동 만들지 않음.
- **테스트 한계**: 실제 발동 드뭄 → 수동 테스트 발송 + 가짜 데이터 주입 검증으로 대체. 실제 발동 시 사후 점검 필요.
- **오탐/미탐**: 1겹 지수추정은 10분 스냅샷 한계로 짧은 발동 놓칠 수 있음. 스크레이프가 보완하되 둘 다 실패 가능성 명시.
- **카톡 지연**: 감지 10분 + 발송 동일 스텝 → 실사용 ~10~15분 지연. 메시지에 지연 고지 포함.

## 10. 구현 순서(요약)

1. 감지 소스 확정/검증(KRX·네이버 파싱 가능성). 결과로 스크레이프 가능 범위 결정.
2. `fetch_data.py` `detect_market_halts()` + 스키마.
3. `validate_data.py` 검증 추가.
4. `index.html` 배너 + 배지 + 이력표.
5. `check_halts.py` + `fetch-data.yml` 스텝 + `halts_state.json`.
6. 검증(렌더·가짜주입·테스트발송) + `CLAUDE.md` 갱신.
