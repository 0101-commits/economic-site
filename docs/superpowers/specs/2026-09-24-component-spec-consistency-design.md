# economic-site 화면·컴포넌트 통일 6차 — 컴포넌트 규격서 + 마감 개편안

작성 2026-09-24 · 대상 `index.html` + `js/app0~7.js` + `css/seed/seed.css`(벤더) · 상태 **기획, 구현 미착수**

앞선 기획 4벌(IA 9/18 · 가독성 9/19 · 조작·전환 9/21 · 구조 통일 9/21~22, 5차까지 구현·배포)이 같은 벤치 자료(네이버 PC·반응형, 토스 PC 180컷)로 만든 결정을 **폐기하지 않고 흡수**한다. 이 문서가 새로 하는 일은 셋이다.

1. **2026-09-24 현행 화면을 다시 재서**(88라우트, 1440·390) 앞선 기획이 남긴 것과 새로 갈라진 것을 숫자로 잡는다. 기획서 문구를 믿지 않고 DOM 을 잰 이유는 앞선 4벌에서 진단 25건이 재측정에서 내용이 바뀌었기 때문이다(`raw/PRIOR-DECISIONS.md` §4).
2. **컴포넌트 규격서를 한 문서로 고정**한다(§4). 지금까지 규칙은 CLAUDE.md 문단·게이트 코드·기획서 셋에 흩어져 있어 "버튼은 어떻게 만들어야 하나"에 한 곳이 답하지 않았다.
3. 5차가 "남은 것"으로 넘긴 축(실행 버튼·나머지 칩 묶음·행 클릭 영역)과 이번에 새로 잡힌 갈림을 **한 로드맵**으로 마감한다(§7).

무게는 사용자 결정대로 **통일감(컴포넌트·페이지 골격)** 과 **가독성(타이포·숫자·색·밀도)** 두 축이다. 고도화(벤치 기능 이식)와 모바일 별도 축은 이번 범위 밖이다.

## 3. 원칙

기존 원칙(SEED 토큰만 · 색=데이터 · 밀도는 행으로 · 크기/굵기는 스케일만 · 차트 색은 토큰)은 그대로다. 이번에 셋을 더한다.

1. **규칙은 부품이 강제한다.** 순서·크기·선택 표시처럼 "이렇게 하라"는 규칙은 CLAUDE.md 문장이 아니라 **공용 함수 하나 또는 클래스 하나**가 만든다. 규칙만 있고 부품이 없으면 위젯 93개가 각자 만들고, 그 결과가 U12·U13 이다.
2. **한 역할 = 한 부품 = 한 겉모습.** 같은 일을 하는 컨트롤(기간 고르기·실행·이동·접기)은 화면이 달라도 같은 높이·모서리·굵기다. 역할이 다르면(탭 vs 칩, 제목 vs KPI 라벨) 겉모습도 달라야 한다 — 통일은 "다 똑같이"가 아니라 **역할마다 하나**다.
3. **벤치는 규칙의 방향이고 값은 SEED 에서 꺼낸다.** 벤치 셋이 일치하는 것(제목 검정·등락은 값 아래·실행 버튼 자리 한 곳·수동 새로고침 없음)은 따른다. 값(높이·반경·간격)은 벤치 숫자가 아니라 SEED 토큰(x8=32, radius-full, t4/t6…)으로 옮긴다 — 벤치 값을 그대로 쓰면 스케일 밖 값(27·45·58·반경 7)이 다시 들어온다.

### 4.8 위젯 헤더 `econWidgetHead()`

헤더는 **한 함수가 만든다**. 마크업에 박힌 헤더는 함수가 읽어 재배치한다.

```
[h3 제목][.w-meta: 단위 · 원본 화면 › · as-of 칩(정상이면 침묵)] ……… [.w-tools: 별 · 새로고침 · 접기]
                                     (아래 줄, 있을 때만) [.w-ctl: 기간 칩 묶음 | 단위 칩 묶음 | 토글]
```

| 슬롯 | 규칙 |
|---|---|
| 제목 | `h3.widget-title` t4 14/700 `--c-txt`. 1줄. 부제(설명)는 `.w-sub` t2 muted 제목 아래 — 현행 3개 |
| 메타 | 제목 오른쪽 같은 줄, t2 muted. 순서 고정: 단위 → 「원본 화면 ›」 → as-of. 벤치(토스 「09.19 13:29 기준」·네이버 「2026.09.18. 기준」) 자리와 같다 |
| 도구 | 오른쪽 끝, 아이콘 버튼 28 만. **순서 고정: 별 → 새로고침 → 접기**. 별 = 레지스트리가 아는 지표 제목이면 항상(S2) · 새로고침 = §4.3 조건 · 접기 = 높이 ≥240 만(S2) |
| 컨트롤 줄 | 헤더 아래 줄. 칩 묶음만(§4.4). 실행 버튼은 도구 슬롯으로 올린다 |
| 헤더 높이 | 1줄 **32** · 컨트롤 줄 있으면 +44(칩 32 + x3) |

- 제목 없는 위젯 8개(띠·details 3·노트·스터디 2·거래정지 이력)는 `.widget--bare` 로 표시하고 헤더 함수가 건너뛴다. 단, **거래정지 이력**(`#marketHaltHistory`)은 제목이 필요한 데이터 위젯 → 제목 부여.
- 세 주입기(`app1.js:544~` 새로고침 · `app3.js:2117` 접기 · `app4.js:910` 별)는 **슬롯에 넣기만** 하고 순서는 함수가 정한다(`appendChild` → 슬롯 `insert`).
- 현행 갈림: U11·U12(31가지 → 1). 벤치: 헤더 오른쪽 요소 1종 1자리.

## 10. 리스크·함정 (구현자에게)

1. **C1 은 71개 위젯의 첫인상을 바꾼다.** 파랑 제목이 사라지면 화면이 "회색 텍스처"로 돌아갈 위험 — 9/18 「Phase 3 위계 격상」이 그걸 피하려 파랑을 넣었다. 700 굵기 + 헤더 32px 고정 + 위젯 간격 16 이 위계를 대신하는지 P0 직후 shots 로 확인. 부족하면 제목 t5 16 으로 한 단 올리는 것이 다음 수(파랑 복귀 아님).
2. **`WCOLLAPSE_DEFAULT_COLLAPSED_NARROW` 는 제목 텍스트 부분일치**(9/18 함정) — C2 가 제목 DOM 을 재배치해도 `textContent` 는 유지해야 한다. 헤더 함수가 제목 노드를 옮기지 말고 슬롯을 **옆에** 세울 것.
3. **`.econ-search{display:flex}` 가 `[hidden]` 을 이기는 선례** — 새 `.econ-iconbtn`·`.w-tools` 에 display 를 주면 숨김 상태와 싸울 수 있다. `:where()` 특이성 0 리셋 관행 유지.
4. **SEED `data-checked` 와 `aria-pressed` 둘을 세워야 한다** — recipe 는 `[data-checked]` 만 본다(U16 원인). `econChipSelect` 가 둘 다 쓰고, CSS 자작 규칙은 `[aria-pressed=true]` 만 본다.
5. **C4 필 탭→칩은 `ECON_VIEW` 축 이동**(t→f). 옛 `?t=` 딥링크는 별칭으로 해석(리다이렉트 아님, IA 확정 방식).
6. **거시 카드 배경 리터럴은 다크에서 의도된 3% 흰색**일 수 있다 — 토큰(`--c-surface-2`)이 다크에서 같은 명도인지 K 축 재측정.
7. **S22 는 부하에 민감**(4차) — 게이트 넷 연달아 돌리지 말 것.
8. 헤더 새로고침 제거 대상 판정은 **위젯이 라이브 프록시를 부르는지**로 — `refreshChartByCanvasId` 대상 canvas 목록이 그 집합이다. 목록 밖 위젯의 버튼이 지금 무엇을 하는지(`data.json` 재적용?) 먼저 확인.
9. 백슬래시 든 문자열(정렬 표식 등)은 heredoc 금지, Write/Edit 로(9/21 재발 기록).
10. `.omc/research/struct-2026-09-24/` 는 로컬 전용·미커밋. 스크립트는 재현 가능하게 남겼으니 P0 뒤 같은 스크립트로 재측정해 §1 표를 갱신한다.
