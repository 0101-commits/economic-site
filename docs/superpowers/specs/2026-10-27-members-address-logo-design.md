## 1. 왜

ecom 은 주인 1명이 여러 기기에서 쓰도록 자랐다. 이제 **ECOM 모임 사람 몇 명**이 각자 들어와 자기 관심 종목 · 알림 조건 · 보유를 따로 쓰게 한다. 함께 주소를 짧게 바꾸고(지금 `0101-commits.github.io/economic-site/`), ECOM 모임의 원래 로고를 앱에 입힌다.

## 3. 목표 · 하지 않을 것 · 실패로 볼 것

**목표**
- G1 키 없는 기기로 새 주소를 열면 입장 화면이 먼저 뜬다. 키를 한 번 넣으면 그 기기는 다음부터 바로 홈.

- G4 시장 자료(data.json · 묶음 · AI 요약 · 브리핑)는 모두가 같은 것을 본다.
- G5 ECOM 로고가 머리줄 · 입장 화면 · 앱 아이콘 · 파비콘 · 공유 미리보기 · 폰 알림 아이콘에 들어간다.

- 아이디·비밀번호 · 구글/카카오 로그인 · 이메일 · 비밀번호 찾기.

- 멤버 카톡 알림(카톡은 주인 계정 「나와의 채팅」 구조라 멤버에게 못 보냄. 멤버 알림 = 웹 푸시).
- 도메인 구입 · 유료 요금제.
- 시장 자료 수집 파이프라인 변경(수집기는 그대로).

**실패로 볼 것(돌아가도 실패)**
- 한 멤버의 관심 · 조건 · 보유가 다른 멤버 화면이나 알림에 섞임.

- 무료 한도(Cloudflare Workers 하루 10만 요청 · KV 쓰기 하루 1,000)를 넘겨 사이트나 알림이 멈춤.
- 로고가 등락 색(빨강 상승 · 파랑 하락, 서양식 설정에선 초록 상승)과 섞여 숫자의 뜻을 흐림.

## 5. 설계

### 5-1 사람 표(Worker KV)

**[설계 판단]** 칸 이름을 키 해시가 아니라 **사람 id(uid)** 로 바꾼다 — 키를 다시 만들어도 칸이 그대로라 복사가 필요 없다(현행 `/sync-key` 바꾸기는 prefs 만 복사하고 push 는 안 옮김).

```
user:<uid>            { uid, name, role: "owner"|"member", status: "active"|"paused",
                        keyHash, createdAt, lastSeenDay, aiDay, aiCount }
ukey:<keyHash 전체>   uid            ← 요청마다 한 번 읽는 조회표
users:index           [uid, …]      ← KV list 는 무료 하루 1,000회라 쓰지 않는다
prefs:<uid>           (현행 prefs 문서 그대로)
push:<uid>            (현행 구독 목록 그대로)
hold:<uid>            (현행 encHoldings 덩어리 그대로)
hold:<uid>:prev:<KST 날짜>   (현행 이전 판 규칙 그대로, 30일)
```

- uid = 무작위 12자(소문자+숫자). 공개 파일에 실어도 사람을 알 수 없다.
- 해석기 하나: `_resolveUser(env, keyHash)` → `ukey:` 조회 → `user:` 읽기 → `status === "active"` 아니면 401(`paused` 면 403 `paused`). 모든 인증 경로(`/prefs` · `/push/*` · `/portfolio` · `/ai` · `/sync-key` · 새 `/me` · `/admin/*`)가 이것만 쓴다. Worker 메모리에 60초 캐시(조회 비용 절감, 정지는 최대 60초 늦게 반영 — 허용).
- `lastSeenDay` 는 하루 1회만 쓴다(KV 쓰기 하루 1,000 한도).

### 5-2 입장 키

- **[권고·승인 대기]** 형식 `ECOM-XXXX-XXXX-XXXX`(헷갈리는 0 O 1 I L 뺀 31글자 중 12자 ≈ 59비트). 주인이 발급, **화면에 한 번만** 보여 주고 서버엔 SHA-256 해시만.
- 입력은 대소문자 · 하이픈 · 공백을 무시하고 정규화한 뒤 해시(현행 `trim` 규칙 확장). 해시 방식은 현행과 같다(`SHA-256(정규화 키)`) — 주인의 지금 동기화 키도 같은 함수로 들어오게.
- 기기에는 현행처럼 해시와 보유 열쇠만 남는다(원문 저장 없음). 요청 인증도 현행 헤더 `X-Sync-Key-Hash` 를 그대로 쓴다 **[설계 판단: 세션 토큰을 새로 만들지 않음 — 발급 키가 무작위라 해시를 소지 증표로 써도 대입 공격이 성립하지 않고, 앱 코드 변경이 가장 작다]**.
- 키 잃어버림 → 주인이 「키 다시 만들기」 → 옛 키 즉시 무효. **보유는 키에서 만든 열쇠로 잠겨 있으므로 새 키로는 못 연다** — 옛 키가 남은 기기가 있으면 그 기기에서 새 키로 다시 잠가 올린다(현행 「키 바꾸기」 흐름), 없으면 보유를 다시 넣는다. 화면에 이 사실을 키 다시 만들기 확인 단계에서 알린다.
- 본인 키 바꾸기(옛 키를 알 때) = 현행 `/sync-key` 바꾸기 흐름을 사람 표 기준으로 고친다(`ukey:` 옛 것 지우고 새 것 넣기, 보유 다시 잠금).
- 대입 방어: 현행 `AI_LIMITER`(IP당 분당 10회)를 입장에도 건다. 59비트라 충분.

### 5-3 주인 이전(첫 배포 때 한 번)

1. 지금 유효한 동기화 키 해시(`_expectedSyncKeyHash`)로 `user:<ownerUid>`(role owner) + `ukey:` 를 만든다 → **주인은 지금 키 그대로 입장**(다시 로그인 불필요).
2. `prefs:<옛 hash16>` → `prefs:<ownerUid>`, `push:<옛 hash16>` → `push:<ownerUid>`, `portfolio:encHoldings`(+prev) → `hold:<ownerUid>`(+prev) 복사. 옛 키는 30일 남겨 둔다(되돌리기용).
3. 이전은 Worker 의 일회성 관리 경로(주인 키 + `X-Push-Read-Key` 둘 다 요구)나 `wrangler kv` 스크립트로 한다 **[설계 판단]**. 멱등이어야 한다(두 번 돌려도 같은 결과).
4. `alerts_config.json` 은 **주인 것으로 그대로 둔다**(수집기 6곳이 관심 종목 목록으로 읽음). 멤버 관심은 거기에 절대 넣지 않는다.

### 5-4 Worker 경로

| 경로 | 인증 | 내용 |
|---|---|---|
| `GET /me` | 키 해시 | `{uid, name, role}` — 입장 확인 · 머리줄 이름 |
| `GET·PUT /prefs`, `GET·PUT·DELETE /push/subscribe`, `GET·POST /portfolio`, `POST /ai`, `POST /sync-key` | 키 해시 → `_resolveUser` | 현행 그대로, 칸만 `<uid>` |
| `GET /admin/users` | 주인 | 목록(uid · 이름 · 역할 · 상태 · lastSeenDay · 폰 알림 기기 수) — 키 해시는 내보내지 않음 |
| `POST /admin/users` `{name}` | 주인 | 사람 만들기 → 응답에 **키 원문 1회** |
| `PATCH /admin/users/:uid` `{name?, status?}` | 주인 | 이름 · 멈춤/다시 열기 |
| `POST /admin/users/:uid/rekey` | 주인 | 새 키(원문 1회), 옛 `ukey:` 삭제 |
| `DELETE /admin/users/:uid` | 주인 | 사람 + 칸(prefs · push · hold) 전부 삭제. 주인 자신은 못 지움 |
| `GET /prefs/all`, `GET /push/subscriptions/all`, `PUT /push/prune` | `X-Push-Read-Key` | CI 용 읽기 전용: `[{uid, role, prefs}]` · `[{uid, quiet, subs}]` (active 만). 옛 단수 경로는 주인 칸을 돌려주는 호환 경로로 한동안 유지 |

- CORS `ALLOWED_ORIGINS` 에 `https://ecom-terminal.pages.dev` 추가(옛 주소도 유지). 미리보기 배포 주소(`*.ecom-terminal.pages.dev`)는 넣지 않는다.
- `/ai` 사람별 하루 한도 **[권고·승인 대기: 멤버 하루 30회, 주인 무제한]** — `user:` 의 `aiDay/aiCount` 로 센다(KV 쓰기가 호출마다 1회 → 멤버 수 × 30 이 하루 1,000 쓰기 한도 안에 들어야 함).

### 5-5 앱 화면(`app/`)

- **입장 화면** 새 라우트 `/welcome`. 기기에 키 해시가 없으면 모든 라우트가 여기로 간다 **[권고·승인 대기: 키 없이 시장 화면 둘러보기 허용 안 함]**. 구성 = ECOM 로고(마크 + 글자 + 영문 문구) · 한 줄 소개 · 입장 키 칸 1개 · [들어가기] · 「키는 모임 운영자에게 받습니다」. 성공 → `GET /me` → 「○○님, 어서 오세요」 짧은 확인 → 원래 가려던 화면.
  - 오류 문구: 키가 틀림 / 멈춘 키(운영자에게 문의) / 시도가 많음(1분 뒤) / 연결 안 됨(다시 시도).
  - 화면 데이터 파일(data.json 등)은 공개 그대로라 이 입장은 **화면 가림막**이다(현행 PIN 과 같은 성격). 기획서에 그대로 적는다.
- **PIN 은 그대로**(기기 잠금, 내 자산 · 설정). 입장 키와 별개.
- **머리줄**: 「ecom」 글자 → ECOM 마크(24px) + 「ECOM」 글자, 오른쪽 끝에 사람 이름 첫 글자 동그라미 → 누르면 이름 · 「이 기기에서 나가기」 · (주인) 「멤버 관리」.
- **설정 › 기기 연결 → 「내 계정」**: 이름 · 입장 키 바꾸기(현행 키 바꾸기) · 이 기기에서 나가기(현행 「이 기기 잊기」 = 해시 · 보유 열쇠 · 기기 안 개인 자료 지움, PIN 은 둠).
- **설정 › 멤버 관리(주인만)**: 목록 행 = 이름 · 상태 배지(사용 중/멈춤) · 마지막 접속일 · 폰 알림 기기 수. [멤버 추가] → 이름 → 키 1회 표시 + 복사 + 「카톡으로 보낼 문구 복사」(주소 + 키 + 한 줄 안내). 행 메뉴 = 이름 바꾸기 · 멈추기/다시 열기 · 키 다시 만들기 · 지우기(확인 단계에서 지워지는 것 나열).

### 5-9 내 자산 · 관심 — 멤버마다 다름 [사용자 결정 2026-10-27 「멤버별로 자산을 다르게」]

- **보유(종목 · 수량 · 평단가 · 매입 환율)**: 멤버마다 `hold:<uid>` 한 칸, 본인 키로 만든 열쇠로 잠금(현행 종단 암호 방식 그대로). 어느 기기든 그 멤버 키로 들어오면 그 멤버 보유가 열린다. 주인도 못 연다.
- **관심 종목 · 지표**: 멤버마다 `prefs:<uid>` 의 `econ_watch_v1`. 별표 · 오른쪽 관심 칸 · 홈 관심 칸이 모두 그 멤버 것.
- **원장(입출금 · 배당) · 스냅샷(일별 평가액)**: 지금처럼 기기 안에 두되 **저장 이름에 uid 를 붙인다**(`pfLedgerV1:<uid>`, `pfSnapshotsV1:<uid>`, 기기 안 `portfolioV1:<uid>` 사본도 같음). 같은 기기에서 다른 멤버로 바꿔 들어와도 섞이지 않고, 나갔다 다시 들어오면 그대로 돌아온다. 주인의 지금 자료는 첫 입장 때 `:<ownerUid>` 이름으로 옮긴다(복사 후 확인, 옛 이름은 한 번 더 들어온 뒤 지움).
- 시세: 멤버 보유 종목은 Worker `/quotes` 실시간 조회로 평가(수집 목록 불필요).
- 시험: 멤버 A · B 를 한 기기에서 번갈아 입장 → 서로의 보유 · 원장 · 관심이 안 보이고, 각자 다시 들어오면 그대로.
- 다음 단계 후보(이번 범위 밖): 원장 · 스냅샷도 보유처럼 잠가서 서버에 맞추기(기기를 바꿔도 따라오게).

## 6-1. 빌더 검토 반영(2026-10-27) — 설계 판단

빌더 검토(설계만 읽고 계획을 세울 때 막히는 곳)에서 나온 7건의 답. 모두 **[설계 판단]**, D7 만 사용자 결정표로 올림.

1. **키 정규화 범위** — 대소문자·하이픈·공백 무시는 `ECOM-` 형식(접두 `ECOM` + 12자 영숫자)으로 읽히는 입력에만 적용한다. 그 밖의 키(주인의 지금 동기화 키 등)는 현행 규칙(`trim` 만) 그대로 해시한다. `holdKeyOf` 도 같은 정규화 함수 하나를 거친다 → 주인 키 해시 · 보유 열쇠가 바뀌지 않는다. 시험: 주인 키 원문 그대로 입장 + 보유 복호화.
2. **멤버 관심 종목의 수집** — 수집 목록(`alerts_config.json`)에 넣지 않는다. 시세 · 차트 · 알림 판정은 Worker `/quotes` · `check_alerts.get_snapshot` 실시간 조회로 전 종목 동작. 수급(`stockFlows`) · 「왜 움직였나」(`stockReasons`)는 수집 중인 종목(주인 관심 + 거래대금 상위)만, 그 밖은 「수집 대상이 아닌 종목」 한 줄. → 기획서 결정 **D7**.
3. **공개 원장 `events/` 의 멤버 행** — 멤버(role member)의 사용자 조건 사건(U1 · U2 · 종목 B1)은 **공개 원장에 쓰지 않는다**. 발송 기록은 KV `fired:<uid>`(최근 50건, 실제 발송 때만 1회 쓰기)에 두고, 앱 알림 화면의 「받은 알림」은 멤버면 `GET /fired` 로 읽는다. 시장 전체 사건 행은 지금처럼 공개 원장(이름 · uid 없음). 주인 행은 현행 유지.
4. **사람별 발송 상태** — 넘는 순간 판정(`side` · `armedAt`) · 쿨다운은 공개 `alerts_state.json._prefs` 에 키 `HMAC(ALERTS_STATE_SALT, uid + ":" + 조건 id)` 로 둔다(값은 지금처럼 u/d 한 글자와 시각뿐 — 대상 · 임계 없음). 하루 상한 셈은 `fired:<uid>` 의 오늘 건수로. **KV 쓰기 예산(멤버 1명 하루)**: AI 30 + 발송 기록 ≤10 + 접속일 1 + 설정 저장 ≈5 + 보유 이전 판 ≤1 ≈ 47 → 멤버 6명 + 주인 ≈ 350/1,000.
5. **옛 단수 CI 경로** — `GET /prefs` · `/push/subscriptions`(+`X-Push-Read-Key`)는 **주인 칸 고정**으로 남긴다. 배포 순서 = Worker(복수 경로 추가 + 단수 = 주인) → 파이썬(복수 경로로 전환) → P4 실발송 확인 뒤 단수 경로 삭제.
6. **P1~P2 동안 새 주소** — 열어 둔다. 내용은 옛 주소와 같은 공개 화면이고, 입장 화면은 P3 에서 켠다. 멤버 초대는 P3 뒤.
7. **인증 실패 처리(앱)** — `401`(키 무효 · 다시 만들어짐 · 지워짐) → 기기의 키 해시 · 보유 열쇠만 지우고 입장 화면 + 「키가 바뀌었거나 지워졌습니다. 운영자에게 새 키를 받으세요」. `403 paused` → 아무것도 지우지 않고 입장 화면 + 「멈춘 키입니다」. 두 경우 모두 기기 기록(원장 · 스냅샷 · PIN)은 그대로.

## 7. 만드는 사람에게 맡김

- uid · 키 생성 세부 함수, Worker 캐시 방식, 화면 문구의 최종 다듬기(ux-writing-ko 규칙), 관리 화면의 행 메뉴 모양, SVG 다각형 좌표 추출 방법(손으로 / potrace 등).
- 단, 5절의 KV 이름 · 공개 파일 금지 · 무료 한도 · 색 범위는 바꾸지 않는다.

## 8. 위험

- **무료 한도**: Workers 하루 10만 요청(계정 공유), KV 쓰기 하루 1,000 · list 1,000. 넘김 방식 · AI 한도 · lastSeen 하루 1회 쓰기로 관리, P1 뒤 2주 실측.
- **주인 자료 손실**: 이전은 복사(옛 칸 30일 보존) · 멱등 · 되돌리기 경로 유지.
- **멤버 사생활**: 보유는 종단 암호라 주인도 못 본다. 관심 종목 · 알림 조건은 Worker KV 에 평문 — 주인(Cloudflare 계정 소유자)은 기술적으로 볼 수 있다. 입장 화면이나 초대 문구에 한 줄로 밝힌다.
- **공개 데이터**: 입장은 화면 가림막이고 시장 자료 파일은 공개 그대로다.

## 구현 중 바뀐 결정(2026-10-27)

컨트롤러 판정으로 설계서가 바뀐 곳.

- (a) 마스터는 기기 키 접미사 없이 옛 키를 그대로 쓰고, 멤버만 `base:<uid>` 를 쓴다(5-9 는 전부 접미사였음).
- (b) 멤버 AI 횟수는 `aiq:<uid>`, 마지막 접속은 `seen:<uid>` 에 둔다(사람 기록 `user:<uid>` 에 넣지 않음).
- (c) 멤버 하루 상한은 `alerts_state` `_prefs` 의 공개 HMAC 카운터로 센다(6-1 4번은 `fired:<uid>` 를 세라 했으나 CI 가 읽지 못함).
- (d) 멤버 시장 사건 쿨다운은 같은 키의 앞선 공개 이력 행이 하나라도 있으면 적용한다.
- (e) 조용한 시간에 걸린 멤버 조건은 아침에 다시 보내지 않는다.
- (f) `/push/subscriptions` 응답이 마스터 `uid` 를 돌려준다.
