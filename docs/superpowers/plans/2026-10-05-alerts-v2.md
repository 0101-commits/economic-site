# 알림 v2 구현 계획 (사건 사전 · 원장 · 등급 · 카톡 · 편성표)

> **For agentic workers:** 이 문서는 에이전트 계약서다. 과제마다 「파일 · 접점 · 검사」가 있고, 사전(events.yml) · 원장(ledger) · 등급(level) 이름은 여기 정의가 단일 원천이다. 과제 사이 이름이 어긋나면 파리티 검사(G1)가 실패한다.

**Goal:** 알림을 「시각 발송」에서 「사건 발송」으로 바꾼다 — 사전 36 × 데이터 → 원장 → 구독 → 편성 → 발송(푸시 · 카톡 · 디스코드) → 보관(화면).

**Architecture:** 데이터 층(수집 런 · 번들 · Worker)은 그대로. `scripts/alerts_v2/` 패키지가 판정 → 원장(`events/YYYY-MM-DD.json`, 멱등) → 편성 → 발송을 맡고, 현행 판정기 5개(check_swings · check_halts · check_releases · check_mer_thresholds · check_alerts 의 /prefs 판정)는 추출기 안의 함수로 흡수한다. 전환은 저장소 변수 `ALERTS_V2`(`0`=원장만 쓰고 발송 없음, `1`=v2 발송 + 현행 발송 단계 건너뜀)로 단계적.

**Spec:** 기획서 v2 https://claude.ai/artifact/93GornDyzLc6rfrZcu4QXV (원본 `scratchpad/alert/ecom_alert_plan_v1.html`). 장 번호: 3 사건 사전 · 4 문구 · 5 카톡 · 6 편성표 · 7 설정 · 8 발송 · 9 데이터 · 10 게이트 · 11 로드맵.

## Global Constraints

- Python 3.11, 표준 라이브러리 + requests · matplotlib · pywebpush(기존). 새 의존성 금지.
- 앱: Vite 8 + React 18 + TS + Tailwind v4, HashRouter. 토큰 밖 색 금지(`app/src/styles/tokens.css`), 장식 0.
- 라벨 · 이름은 사전(events.yml)에서만. 코드 · 화면 · 문구에 사건 이름을 글자로 적지 않는다(G1).
- 내 자산 금액은 원장 · 푸시 · 카톡 · 디스코드 어디에도 싣지 않는다(G5). 사용자 조건의 임계값은 원장에 넣지 않는다.
- 상대 시점어(내일 · 다음 주 · 연휴) 금지, 날짜로(현행 `slot_line_ok` 승계).
- 제목 ≤30자(브리핑 48 상한), 푸시 본문 ≤80(40×2), 디스코드 한 통 ≤1,500자, 카톡 텍스트 200 · 행 5 · 버튼 2 · 버튼 8자.
- 커밋 메시지에 배포 명령 글자(wrangler deploy 등) 금지(승인 훅 오탐). Worker(`cloudflare-worker/`) 파일 커밋은 팀장이 따로(승인 필요).
- 테스트는 `python -m pytest scripts/tests -q` 전체가 통과해야 커밋. 테스트 실행 뒤 `git checkout -- mer_signals.json`(봇 파일 더럽힘).
- 이 PC 메모리 1~4GB: Playwright 는 한 번에 하나, 에이전트마다 고유 포트. 긴 테스트는 `-x` 로 빨리 끊기.
- 한국어 보고서체, 영어식 · 개발자 표현 지양(파일 · 함수 이름은 그대로).

## 단일 원천 — 이름과 모양

### 등급 `level`
`alarm`(경보) · `alert`(알림) · `notice`(안내) · `record`(기록). 브리핑은 `brief`, 운영은 `ops`(원장 밖).

### 꾸러미 `package`
`quiet`(경보 + 사용자 조건 + 아침) · `normal`(기본, 상한 6, 아침 · 마감 · 주간) · `many`(안내도 울림, 상한 12, 브리핑 6).

### 세기 `strength`
`normal`=2.0σ · `big`=2.5σ(기본) · `huge`=3.0σ · `value`(직접 값). σ = 직전 250일 일간 수익률 표준편차(현행 `check_swings` 정의), 임계 = min(max(kσ, 0.5%), 5%).

### 평가 런 `run`
`light`(장중 매분, 값 5분) · `full`(매시 풀 런 끝) · `settle`(평일 18:00) · `daily`(일일 런 끝) · `eve`(21:00) · `brief:<slot>`.

### 사전 행 `events.yml`
```yaml
- id: D1
  name: 외국인 연속 시작
  family: D                 # A 급변 · B 기록 · C 임계 · D 수급 · E 일정 · F 공시 · G 렌즈 · H 실물
  level: alert              # 기본 등급
  escalate: {cond: "streak>=10", to: alarm}   # 선택
  targets: [kospi]          # 레지스트리 id(bundles/registry.json) 또는 별칭(ALIASES)
  default_on: [kospi]       # 처음부터 켜짐. 비면 「관심」(별표)만
  judge: flow_streak_start  # events.JUDGES 의 함수 이름
  params: {days: 5}
  run: settle
  cooldown: {per: [target, dir], days: 1}
  title: "외국인 {days}일째 {dir_ko} · 오늘 {value}"
  why: ["5일 누적 {cum5} · {supporter}가 받침"]
  next: ["확정 18:00 · 순매수로 돌아서면 알림"]
  url: "#/market?a=flow"
```
필수 키: id · name · family · level · targets · judge · run · title · url. 그 밖은 선택. `schema.load_events()` 가 검증한다.

### 원장 행 `events/YYYY-MM-DD.json` (배열, 추가만)
```json
{"key":"D1:kospi:sell:2026-10-01","event":"D1","target":"kospi","dir":"sell","level":"alert",
 "value":-2040,"unit":"억","asOf":"2026-10-01","fresh":"prev",
 "title":"외국인 5일째 순매도 · 오늘 −2,040억","why":"5일 누적 −7.9조 · 기관 순매수가 받침",
 "next":"확정 18:00 · 순매수로 돌아서면 알림","url":"#/market?a=flow",
 "ts":"2026-10-01T18:05:12+09:00",
 "sent":{"push":0,"kakao":false,"discord":false,"bundled":false,"held":false}}
```
`key` = `{event}:{target}:{dir}:{asOf 또는 KST 날짜}`. 같은 key 는 두 번 들어가지 않는다(`Ledger.append` 가 False 반환). 사용자 조건(U1 · U2)의 key 는 `ALERTS_STATE_SALT` HMAC 12자, `target`은 지표 id, `value`는 현재값(임계값 아님).

`events/latest.json` = 최근 7일 행을 합친 배열(화면이 읽는 유일한 파일). `Ledger.rebuild_latest()` 가 만든다.

### 판정 함수 계약 `events.JUDGES[name](ctx, ev) -> list[Hit]`
```python
@dataclass
class Hit:
    target: str; dir: str              # dir: up|down|sell|buy|cross|near|new|change|enter|exit
    value: float|str|None; unit: str   # 표시용 값
    asOf: str; fresh: str              # 번들 신선도 5종 live|prev|stale|kept|missing
    chg: float|None = None             # 등락(%)
    fields: dict = field(default_factory=dict)   # 문구 틀 변수(streak, cum5, line, dist …)
```
`ctx = context.Context.load(now)` — `ctx.value(target)` 는 번들 값(단일 원천), `ctx.series(target, n)` 일봉, `ctx.registry[id]`, `ctx.mer`, `ctx.data`, `ctx.bundles`, `ctx.calendar`.

### 설정 `/prefs` v2 (Worker KV, 화면 타입 `Prefs`)
```ts
type Level='alarm'|'alert'|'notice'|'record'; type Strength='normal'|'big'|'huge'|'value'
type AlertCond = { id; event: string /* A1..H4|U1|U2 */; target: string; strength?: Strength; value?: number
  level?: Level /* 조정 */; repeat: 'each'|'once'; ring: boolean; enabled: boolean; armedAt?: string; name?: string }
type Settings = { updown; unit; quiet: {from,to}|null; package: 'quiet'|'normal'|'many'
  ringChannel: 'kakao'|'push'|'both'; dailyCap: number; quietAlarm: boolean
  briefings: {morning:boolean; close:boolean; noon:boolean; evening:boolean; us:boolean; weekly:boolean}
  families: Record<'A'|'B'|'C'|'D'|'E'|'F'|'G'|'H', boolean>; rememberKey: boolean
  kakaoRecipients: {uuid:string; name:string; briefOnly:boolean}[] }
type Prefs = { v: 2; alerts: AlertCond[]; settings: Settings; scenarios: ... }
```
v1 문서(`type` 6종)는 읽을 때 변환: price→U1, pct→U2, high52→B1, event→E1, flow→D2(코스피)/D5(종목), lens→C1/C2.
